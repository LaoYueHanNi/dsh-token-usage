模型卡 · 性能入口重设计（示意）

排序归排序，视图归视图：性能不再是第三个「排序项」，而是卡头的独立开关。

问题与设计

  • 歧义：「token｜费用｜最近活跃」是同一份数据的排序方式，「性能」是另一份数据的展示——三者并排在一个 segmented 里，性能看起来像「按性能排序」，实际却换了整个卡的内容。
  • 方案：排序 segmented 保持纯粹（模型卡 = token｜费用）；「性能」独立成卡头右侧的 toggle 按钮（带仪表符号，与排序组视觉分离）——语义是「看另一面」，不是第三个排序项。
  • 性能视图内无排序控件：它的顺序本身就是定义（有效行按速度降序，样本不足/无计时沉底）——没有第二种排法，不出现空的选择。
  • 对照：会话卡「token｜费用｜最近活跃」三个都是排序，保持 segmented 不动；项目卡同理。只有模型卡多一个性能开关。

Every provider-billed call is recorded as it happens — tokens, cost, model, session — and you can read it back from the sidebar's **Token Usage** entry, from **Settings → Token Usage**, or from the **Usage** tab inside a conversation.

## What you can do

- **Read the totals**: the dashboard shows summary cards with cost, a trend chart (hourly for a single day, daily for wider ranges; hover a point for its total), and a five-tab detail block — **projects / models / sessions / providers / runtime overhead**. The date range and model filters are shared, with `1d` / `7d` / `30d` shortcuts; the request card carries **failed** and **overhead** pills.
- **Cut the usage your way**: rows sort by total tokens or cost (sessions also by last activity), project rows aggregate every matching root session, the runtime-overhead tab breaks auxiliary system calls (title generation, automatic review, timeline reports, reasoning translation) down by kind and lists a collapsible web-tools row (web search / web fetch calls) separately, and the by-provider tab lists each provider route key with cache hit rate and billed cost — each entry remembering its own sort choice.
- **Follow one conversation**: the conversation pane's **Usage** tab adds the current session's cards, four-bucket token strip, trend chart and per-model table; switch **Session / With subagents** to include child sessions, drill into each one and back, and hover the failure pill for a per-class breakdown. **Latest request** and **Live requests** also show waiting, streaming, failed and cancelled requests while they run, one row per provider attempt.
- **Know what it costs**: cost is computed per request from per-model rates; click a priced model name for its full price table, or Ctrl+click it to filter the dashboard to that model. The **Pricing table** entry at the end of the filter row opens every model in the cloud feed, and **Model alias associations** beside its title manages the local alias→model links.
- **Watch provider quota**: the button left of the model chip in the input bar shows the selected provider's remaining quota — plan windows, account balance or remaining credits, and every upstream account behind a Magpie gateway.
- **Make it fit**: the **configuration card** on the host's **Plugins** page sets the data directory (a saved absolute path migrates history immediately), the **Pricing region** dropdown (Gitee / GitHub mirror, which also picks ¥ or $), **Pin to sidebar** (which moves the entry out of the **More** menu into a resident sidebar row), and **Show Token Usage in Settings** (on by default; turn off to hide the **Settings → Token Usage** section).

## Some limits

- An unpriced model is billed at ¥0 and flagged; pricing comes only from the cloud mirror synced at startup, so a hand-edited `pricing.json` is no longer read. Costs are reselected from history when rates or rules change.
- History from before installation is backfilled on the first startup (idempotent); unreadable session logs are skipped and counted. Auxiliary calls cannot be backfilled — the host keeps no usage record of them, so recording starts with the first request after upgrading. Web-tool (`web_search` / `web_fetch`) call records can be backfilled from session logs (`tool/call` + `tool/result` are persisted; an existing data directory needs one manual full sync from the settings page), while tokens are counted only when the host reports that turn's usage.
- Usage with no route key is never folded into a named provider: it stays a single dimmed **Missing provider** row (deleted session logs, history older than the route-key field, and runtime overhead such as title generation carry none).
- Saving a new data directory is refused while a conversation is running — wait for it to end. Removing the plugin leaves the data files under `~/.dsh/token-usage/`; delete them yourself if you no longer need them.
- Unsupported providers hide the quota button (Volcengine, ZenMux, Zhipu Team plan, Claude / Codex / Gemini / Grok subscriptions, GitHub Copilot).

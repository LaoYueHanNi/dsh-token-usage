# 0.4.14

## 新增与修复

- 新增**按供应商统计维度**：用量行在压缩、重试、turn/end 与辅助调用等全部路径上记录供应商路由键，`providers.json` 名册按路由 id 保留最新展示名并随数据目录迁移；旧用量行在启动字段补全时回填空路由键。设置面板新增「按供应商」页签、大屏新增「供应商」卡——展示名 · 相对进度条 · 总 token · 缓存命中率 · 已计费用（与按模型同源，价格表更新后自动重算）；排序可在总 token / 费用间切换，两个入口各自记住选择。
- 没有路由键的用量不并入任何供应商，单列成「缺失供应商」余量行、弱化沉底，问号徽标悬停列出封闭原因集（历史会话日志已删除、字段加入前的旧行、标题生成 / 审批等运行开销天然不带路由键）——这是**已知的差额**而不是丢数，各供应商行之和恒等于顶行。
- 修复**供应商维度与顶行失同步导致丢量**：旧格式 rollup 在历史源文件缺失走保留用量回退时，旧数据进了顶行与费率行却留在供应商表之外——同一份数据加不加日期筛选会给出两张不同的供应商表。改为从费率行单一真相来源反推供应商分组后，合并、筛选、会话维度三条路径必然对账一致。
- 新增**压缩后首请求归因标注**：宿主压缩（剪枝 / 摘要）改写前缀导致的缓存失效，落在其后第一条普通请求上；现在该请求的缓存命中提示会并入「压缩所致」因果（区分剪枝簇与摘要来源、附影子 token 量）。只标注、不改缓存判定——归因是启发式，失效严重度取决于最早改写点位置（实测有 93.6% 命中的受影响行）。
- 字段补全**读失败设三轮重试上限**：候选会话连续三轮读失败后盖章放弃，不再因死会话每次启动重扫全部日文件与会话日志且永不结算。
- 加固**本地数据文件完整性**：日文件重写统一 temp + rename 原子覆盖，去掉「先删后改名」进程死在中间丢一整天用量行的窗口；名册读不回（读不动 / JSON 损坏）时不覆盖——展示名不可从会话日志重建，宁可停在无名字状态也不丢；数据目录搬家与启动链串行化、清理 `.tmp` 残留，「旧目录搬了一半」的半搬状态不再出现。
- 界面细节与 README 按**五个明细维度**对齐：未标注余量行不再拉伸供应商标尺、不计入供应商计数，问号徽标可聚焦；README 的数据目录与定价区域入口改指插件页**配置卡**（统计页只读），别名关联改为标题旁按钮开独立弹窗；README 截图按新界面重拍，隐私打码改为 DOM 文本替换，裁剪脚本参数严格校验。

## 升级说明

- 供应商维度的历史覆盖范围取决于会话日志：已删除日志的历史会话、路由键字段加入前的旧行、运行开销类调用永远没有路由键，统一进「缺失供应商」行；升级后首次统计读取会从日文件重建聚合（格式 3→4），用量数值不变，仅回填维度。
- 展示名名册损坏时插件不再自动整份重写：界面降级为显示原始路由 id，等文件恢复为合法 JSON 或该路由再次被使用后自动重建——这是刻意取舍，防止一次读失败抹掉全部展示名。
- 归因标注只影响展示：缓存评估的 band / reason / eligibility 口径零改动，低缓存告警行为与旧版一致。
- 数据目录搬家在刚启动后会等首轮历史同步结束再动手（多等一会儿），保证标记文件不落进源目录、源目录能真正搬空。

## 验证

发布检查通过：类型检查、59 个测试文件／1179 项测试、后端与客户端构建、83 条决策记录校验。

自动化测试覆盖：provider 维度的聚合 / 合并 / 筛选 / 会话维度「行之和 = 顶行」不变式与计费同源；rollup 格式 3→4 升级回填与历史不完整回退；名册「读不回就不覆盖」「读得回就能覆盖」与名册命中 / 键回退；日文件原子替换与数据目录搬家集成组（含启动链串行化）；归因窗口的并簇 / summary 分隔 / live 与历史重扫双路径接线；字段补全三轮计数、耗尽盖章与 malformed 容错；供应商卡与五页签渲染、未标注行不计入供应商数。

# 0.4.9

## 新增与修复

- 修复「运行开销」页签模型明细行不归一的问题：类别行展开后的模型明细此前直接显示路由名（如 `group/glm-5.3-flashx`、`auto/GLM-5.3-Flash`），与按模型表等其余统计口径不一致；现在按 canonical 归一折叠后再展示。
- 落库记录新增 `responseModel` 字段，保存服务商实际响应的模型：在线采集从 `llm/stream` 结束块的回放信封提取，历史扫描从会话事件的消息源中提取；一条记录同时保留请求模型（`model`）与响应模型两个字段，去重键与首写优先逻辑不变。
- 计费与展示优先使用实机响应模型，缺失时回退请求模型，再走既有的 canonical 与别名正则归一；按模型表、趋势图、运行开销明细、模型筛选与费率匹配全部切换到该生效名口径。

## 升级说明

- 响应模型仅 pi-ai 系适配器的回放信封携带（`kind: 'pi-ai'`、`version: 2`）；其他信封（如 deepseek-messages）无该字段，行为与旧版一致，继续按请求模型统计。
- 生效名取响应模型后不再二次回退请求模型：响应模型无法匹配定价表时该行保持未定价并出现在未定价模型列表中，属有意设计（避免静默错价）。
- 旧记录没有 `responseModel` 字段，继续按请求模型统计，不做回填；`rollup.json` 已写入的行保持原样，无需重建。
- 网关 Trial 通道等「请求模型与实际响应模型不一致」的场景自此按响应模型计费与展示，原始请求模型仍保留在记录的 `model` 字段可供对账。

## 验证

发布检查通过：类型检查、48 个测试文件／940 项测试、后端与客户端构建、55 条决策记录校验。

自动化测试覆盖：回放信封响应模型提取（含非法形态拒绝）、事件落库携带与空值省略、在线采集与历史扫描两条路径端到端、聚合分组与请求模型回退口径、响应模型参与筛选与费率匹配、辅助请求明细按响应模型归一折叠。

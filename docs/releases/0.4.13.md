# 0.4.13

## 新增与修复

- 供应商配额按钮按**额度池**聚合读数：magpie 一类网关把同一供应商的多个 Key、多个账号（乃至多个套餐）并列成多张配额卡，网关在它们之间智能路由。此前输入栏的圆圈只读「遇到的第一张卡」，一个账号用尽就把整个供应商画成红色——而流量其实还能路由到其余账号。现在圆圈读该供应商额度池的**均值水位**，并按池内可用性上色：部分账号用尽转黄，池内全部用尽才转红；跨供应商（路由组）各算各的，行为与旧版一致。
- 面板仍逐账号列出各自余量，未做任何合并；「成功/失败」的列头改为更短的「请求」，该列退回一栏普通文本（`成功/失败`），表头与数值同缘，不再占用两词宽度。

## 升级说明

- 额度池的划分以「供应商路由键 + 展示名」为准：同一供应商的多 Key / 多账号共享一池，不同供应商、不同展示名各自独立。套餐不参与分池——网关在同供应商的多个套餐账号之间调度流量，对「还能不能用这个供应商」而言它们是一份预算。
- 路由组模型（`group/…`）与裸模型 id 无法判断实际请求落到哪个供应商，此时各供应商各算各的，圆圈与旧版一致。
- 池水位按各窗口剩余份额的算术平均计算（网关只报百分比、不报各账号的额度绝对值，无法按额度加权）。
- 按模型表的「成功/失败」列不再跨行对齐斜杠（该列改为一栏普通文本）；失败数语义、悬停分项、无失败时不画斜杠等约定不变。

## 验证

发布检查通过：类型检查、56 个测试文件／1133 项测试、后端与客户端构建、77 条决策记录校验。

自动化测试覆盖：额度池归属（同供应商多账号共池、跨供应商与跨套餐分离）、池化均值水位与池内可用性分档、单窗口与旧分档的逐位等价、多 Key 场景下触发器不再误报红色、请求列表头与悬停提示。

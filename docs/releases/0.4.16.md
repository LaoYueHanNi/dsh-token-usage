# 0.4.16

## 新增与修复

- 新增**联网工具调用记录**：联网搜索与网页抓取走工具管线（`dsh-tool-web` → `ctx.web`）而不经过 `ctx.llm`，此前账本完全没有它们。本版在实时监听与历史同步两条路径上配对 `tool/call` 与 `tool/result`，记录每次调用的工具、查询数、轮次、耗时与失败状态（不复制查询原文）；宿主为搜索轮次报告 token 时并入总量与费用，没有报告则只记调用次数、不按次收费，也不进请求池、最新请求与请求序列，避免未计量搜索污染主账请求数。运行开销页与明细页签新增默认展开的「联网工具」行，按固定顺序列出联网搜索与网页抓取各自次数。
- 新增**辅助请求分类升级**：识别宿主 `LlmRequestPurposeMap` 的 `timeline-report`、`auto-review`，未知 purpose 落入 `other` 的同时保留旧宿主 `REVIEW_POLICY` 前缀兼容；实时池与持久记录共用同一分类函数。带 `sessionId` 的 auto-review 与 timeline-report 经去重合并计入会话统计，不再在请求池出现双行或触发缓存过低误报。
- 修复**辅助流 CONTENT_REFUSED 失败口径**：辅助请求被拒绝且已计费时，此前按成功请求计入并丢掉失败码。现在主/辅两条链路统一——失败归因进 failures / failuresByCode，拒绝前已消费的 token 仍计入总量与费用，但不计成功请求数；运行开销 pill、明细行、tooltip 与详情页签的门控共用「requests + failures」计数，仅有失败计费时不再误显空态。同步补齐 `CONTENT_REFUSED`、`ACCOUNT_*` 等 16 个失败码的中英文文案。
- 修复**会话扇出大时统计请求被 431 拒绝**（整页打不开）：此前把 158 个子会话的 id 拼进查询串，URL 达 17.7 KiB，超过 Node 的 16 KiB 请求头上限，且兜底轮询每 5 秒重发同一条失败请求。改为 `root + scope` 表达范围规则、由服务端按落盘血缘展开子树，URL 实测不到 80 字节、与子树规模无关；子会话分组计时在服务端分桶遍历中顺手折叠进 `children.timing`，200 个直接子会话不再重扫日志 200 次；客户端在挂载期对镜像晚到导致的重复请求去重（仅 id 集合变化、同一范围至多复用一次）。
- 修复**已结束子会话的计时两列整列显示「—」**：子会话表平均首 token / token 速度改读服务端折叠的 `row.timing`，不再依赖运行时镜像保留的 `sessionStats` 投影——那份数据在会话结束后就没了，而用量日志里的计时一直存在。统计页注脚写明顶部卡片（投影，含安装前历史）与子会话表（请求记录，仅安装后有计时）的口径差异。
- 适配 **DSH 0.2.2 摘要裁剪**：`sessionStats` 移出 `session.list` 摘要后，子树与钻取子会话的 TTFT / 吞吐改为消费 `fields=session` 下发、与宿主同公式的 timing；`freshnessKey` 改看摘要里的 `tokenUsage`，子代理追加更新时能正确刷新。同时移除随宿主下线的 `@deepseek-ai/dsh-client-ui-settings-plugins` 注入声明、开发依赖与类型导入，并清掉过期的 `package-lock.json` 与 `pnpm-workspace.yaml` 里的设置插件残留条目。
- 修复**对账误删辅助开销**：全量扫描的 `reconcile` 此前会把带真实 `sessionId` 的 `kind: 'aux'` 行当作陈旧行永久删除（实测可一次误删上百条历史，且历史不可回填）。现在按原始 JSON `kind` 走可重建白名单——只有源自会话日志的 `request` / `compaction` / `failure` 允许删除与归属修正，`aux` 及未来未知类型无条件豁免，未改动行按原始文本无损写回；唯一归属的错归 `assistant/message` 原地修正 `sessionId`（保留计时等字段并触发派生缓存失效）。
- 新增**改写前自动滚动备份**：`reconcile`、`refile`、`backfillTiming`、`completeFields` 覆盖日文件前，先把实际改动的文件备份到 `<数据目录>/.backups/<时间戳>-<原因>/`（零改动不建目录、拷贝失败即中止改写、滚动保留最近 5 次）；数据目录搬家时 `.backups/` 随迁并在校验后清理源目录。
- 适配 **Fork 会话继承前缀**：DSH 0.2.2 的 `handle.read()` 返回含继承前缀的完整逻辑日志，此前每次 fork 都会把父会话的压缩费用与失败次数重复计一遍，先扫子会话还会把父消息错归给子会话。现在按 `inheritedEventCount` 切片跳过前缀（SQLite 可跳过父段解压），仅在缺标题或失败缺路由时按需回读折叠；实时监听用 `isOwnSeq` 拦截非自有事件，不落盘也不污染实时池；旧账本由全量扫描自愈（删除重复的 fork 压缩/失败行、修正错归消息）。子代理血缘严格按 `origin === 'subagent'` 判定，保留 `parentSession` 的普通 fork 仍是独立顶级会话。
- 修复**deepseek-chat-import 导入历史污染账本**：导入对话的回复无 usage、路由键是 `deepseek-chat-export`，此前被记成请求行与失败行，虚增请求数与失败数，并在模型/供应商维度多出未定价的 `deepseek-chat-export`。现在识别并跳过该类事件（含 `DEEPSEEK_EXPORT_*` 错误轮次），全量扫描进度与完成提示显示「忽略 N 条 DeepSeek chat 导入记录」，旧账本污染行由对账清理。
- 新增**插件详情页双语正文**：`locale/en.json` 补全 `meta.title/description/detail`，英文界面不再回退 `package.json` 原文；中文描述点出侧栏大屏、设置页签、会话用量页签三处入口，不再是一句话说不清入口在哪。新增用户向 `docs/DETAIL.md` / `docs/DETAIL.zh.md`（「你能做什么 / 一些边界」），并按文件逐项收录进 tarball，不连带 docs 其余内容。
- 修复**worktree 会话在项目维度里单独成项**：`dsh-worktree` 在仓库内建 `<repo>/.dsh/gitworktree/<branch>`，项目维度按 cwd 尾段分组时分支目录被当成独立项目，与仓库本体分裂计数与费用。现在先把 worktree 路径归属到仓库根再分组，tooltip 指向仓库根；存储仍保留原始 cwd。
- 调整**子会话表限高 15 行**：默认只露表头 + 15 行，滚轮归页面；点击（焦点进入）这块列表才接管滚动，点别处自动交还，表头 sticky、滚动条常驻 12%、滚动时加深到 22%。

## 升级说明

- 本版适配 DSH 0.2.2，同时保持对 0.2.1-rc.3 的兼容；旧宿主不提供 `fields=session` 时计时回退原来源。
- 首次统计读取不会整体重建聚合：联网工具维度是可选新维度，旧 `rollup.json` 读作空列表即可，不存在可丢的历史（旧版本就没记录过 web 调用）。
- 升级后历史账本会自愈，数字可能变化：全量扫描会删除 Fork 产生的重复压缩/失败行、修正错归会话的消息，并把 `CONTENT_REFUSED` 拒绝前已计费的 token 补进总量与费用——请求数与失败数不会因此虚增，但费用可能比升级前高（此前漏记）。任何改写前都会落到 `.backups/`。
- 不建议回退旧版：`kind: 'web'` 记录行是新版才有的类型，旧版读取时会忽略，联网工具统计随之消失；`webRows` 聚合同理。
- 数据目录新增 `.backups/` 目录（只在真正发生改写时创建，滚动保留最近 5 次），可随时清空，不影响统计。

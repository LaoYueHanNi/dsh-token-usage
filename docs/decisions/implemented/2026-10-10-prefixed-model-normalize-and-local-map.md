# DR: 提供商前缀兼容、上游别名正则与未定价模型手动关联

Status: implemented

## Problem

提案提出时，插件把云端镜像 `pricing.ccsa.json` 的 `modelId` / `aliases` 展开成精确匹配表。带 `provider/` 前缀的用量名无法命中短名称；上游新增的 `aliasPatterns` 又被加载器丢弃，新增正则别名无法参与计费。相关名称不一致问题见 [GitHub issue #10](https://github.com/LaoYueHanNi/dsh-token-usage/issues/10)。直接使用子串识别会混淆 `glm-5.3-flash` 与价格不同的 `glm-5.3-flashx`，不能据此自动选价。

自动识别仍无法覆盖内部代号等完全异名。用户需要在未定价位置搜索、选择已有价目，并能查看、撤销关联；真正缺少价目的模型需要向上游请求定价。这条补救路径遵守 [废除手工 pricing.json 定价文件机制](2026-09-05-abolish-manual-pricing-json.md)：本机只保存名称关联，不保存价格，不覆盖云端完整规则。

识别必须贯通费用、折叠、筛选、会话视图与「已用」标记，不能只修一处查表。历史 `rollup` 保存的 `RateKey` 也需要更新；给旧的未定价或其他模型规则身份直接套新单价，会错误跳过时间规则、上下文档位和峰谷槽。

## Decision

> [!NOTE]
> 本记录的三个实施阶段均已完成，整体提案于 2026-10-11 转为 implemented。最初设计中的历史 `aliases` 匹配由 [统一正则别名](2026-10-11-regex-only-model-aliases.md) 取代；搜索预填、多字段候选搜索、常驻来源状态与编辑入口、旧 Issue 模板等交互由 [关联入口设计](2026-10-10-pricing-association-entrypoints.md) 取代。以下描述最终落地方案。

**分阶段实施，统一整体边界。** [自动识别与历史重算](2026-10-10-model-pricing-resolution.md) 落实第一阶段；[本地关联后端与迁移保护](2026-10-10-model-pricing-associations.md) 落实第二阶段；[局部关联界面与上游草稿](2026-10-10-model-pricing-association-ui.md) 落实第三阶段。详细接口与组件约定由这些实施记录及后续取代记录维护，本记录保留整体动机、边界与权衡。实现状态不代表已合并 main 或发布，版本与发布仍由用户决定。

**自动识别保留模型身份。** 当前消费端只使用 `modelId` 与 `aliasPatterns`，忽略旧 `aliases`。顺序为原始完整名称的精确 ID → 有效 provider 路径末段的精确 ID → 原名与末段的完整正则匹配。各阶段忽略大小写，唯一命中才结束，歧义立即停止自动识别；正则候选命中取模型并集，同模型去重，跨模型不按数组顺序择一。

归一化仅在各路径段非空时取最后一段，支持多段命名空间；前导、尾随、连续 `/` 不产生候选。不修剪原始名称，不移除版本、标点或 `flash` / `flashx` / `fast` / `pro` / `mini` / `max` 等身份。原始记录和展示名称保留原始拼写，规范 ID 采用当前 feed 的实际拼写。原名 ID 优先于末段 ID，末段 ID 优先于正则。

**整份 feed 验证后启用。** 正则缺省为 `[]`；加载时验证并编译，固定添加 `i`，只接受锚定的字面量、转义标点、分组、分支与可选 `?` 子集，允许模型名中的字面冒号。执行要求匹配起点为 0 且跨度覆盖完整输入，拒绝尾部换行、通配符、无界量词、lookaround、反向引用等不支持语法。非法字段、重复正则或大小写重复 ID 使整份 feed 无效；同步先验证再原子替换，失败保留上一份有效镜像。无有效表时宿主与用量读取继续工作，定价和目标选择明确不可用；真实零单价仍属于已定价。

**本地映射只补救自动失败。** 保存原始完整用量名 → 当前 feed 的精确 `modelId`，来源忽略大小写但不去前缀。不同 provider 的完整名称独立，不允许链式关联、自定义价格或覆盖唯一自动结果；目标完整继承时间规则、上下文档位、峰谷槽和汇率展示规则。保存时重新校验来源和目标，避免旧页面覆盖更新后的自动识别。

自动结果优先，已保存映射仍保留；自动识别再次失败且目标有效时重新生效。目标删除或重命名保留失效条目，不把旧目标当别名追踪。修改或撤销作用于该完整名称及大小写变体的历史和后续用量；撤销后重新自动识别，可能恢复未定价，也可能仍由上游规则定价。管理页保留全部映射与撤销操作，不受日期、模型或会话筛选影响。

**持久化与迁移保护用户选择。** 当前数据目录下独立保存 `pricing-associations.json`，格式版本为 1，包含非负安全整数 `revision` 与来源／目标列表；不存在等价于 revision 0 的空表。未知格式、重复来源、非法字段或损坏内容报告存储错误，不覆写为空表；自动识别仍可用，人工关联读写暂停。

专用读取／保存／撤销接口沿用 same-origin、方法限制、JSON 写入和 `no-store`。客户端提交来源、目标、revision 与 directoryToken；服务端按目录串行化读改写，在锁内检查修订号、目录、当前 feed 与自动识别，原子写入后才返回成功。迁移暂停并排空关联写入；目标同名文件字节不同则拒绝迁移并保留两边，同内容确认后才清理来源，不改变其他自有文件的冲突规则。

**交互在当前用量上下文完成。** 橙色未定价标签打开操作弹窗，提供「关联现有模型」与「增加模型定价」。绑定页默认空搜索，空白输入不列模型；只在模型 ID 字段中忽略大小写做包含匹配，不查正则、family 或其他字段。唯一候选也须显式选择，查看完整定价按需打开子弹窗。保存成功关闭绑定页并刷新统计，失败／冲突保留页面与选择，关闭取消不写入。

全局「模型别名关联」入口位于定价表弹窗标题旁，紧凑列表左侧显示映射、右侧撤销，确认说明按需展开；无常驻状态或查看／修改入口，改绑通过撤销后重新绑定。统计折叠行保留原始关联来源，使用可聚焦问号图标和宿主 Tooltip，hover 延迟 100ms，不使用原生 title 或 help 光标。保存／撤销刷新保留当前筛选、会话树和父弹窗。

上游入口只在未定价操作弹窗提供，以新标签页打开 `https://github.com/LaoYueHanNi/model-price-table/issues/new`。英文标题为 `Add model pricing: {原始模型 ID}`；正文为可选价格参考（四项 token 单价、币种及上下文窗口）、可选官方定价 URL、自动填充的当前定价表版本。名称安全编码，不附带会话、项目路径、请求或凭据，不自动提交 Issue。

**统一上下文并重建历史费率身份。** 费用、规范名、折叠、筛选、未定价列表、会话／子会话、详情与总览已用标记共享同一 feed 与关联快照；按内容、关联及目录变化使缓存失效。正则名称按观察到的输入惰性解析，不把无限候选预先展开。

历史定价指纹当前算法为 3，纳入模型 ID、正则、完整价格规则与有效关联内容。缺指纹或指纹变化时从原始 JSONL／有效记录缓存重建派生聚合，按每条记录当时的时间和上下文重新选择 RateKey，保留原始名称、token 和请求数。缺源历史明确隐藏无法可靠重算的金额，不沿用旧身份伪造精确费用；展示元信息或仅汇率变化不触发规则重选。

[按模型折叠](2026-09-10-bymodel-folds-pricing-aliases.md)、[定价总览](2026-09-05-pricing-table-overview.md)、[模型名定价入口](2026-09-10-bymodel-pricing-name-affordance.md) 和 [daysOfWeek 与三层计价](2026-08-29-daily-slots-days-of-week.md) 的仍有效约定继续保留；已变更的识别、重算和交互边界由对应实施记录标记部分取代，不改变原始日志或上下文 token 口径。

## Alternatives considered

- **直接 contains / 取第一条命中** —— `glm-5.3-flash` 与 `glm-5.3-flashx` 构成实际碰撞，结果还依赖 feed 顺序。子串只能用于人工候选搜索，不能据此自动计费。
- **只在归一化阶段忽略大小写，原始精确和正则仍区分大小写** —— 同一名称会因大小写改变识别结果。按用户要求所有阶段统一忽略大小写，仍保留完整名称和变体边界。
- **严格按上游原名识别，不兼容 provider 前缀** —— 无法解决用户的前缀兼容需求。消费端提供末段候选，保留其余身份与完整正则契约。
- **把每个 provider/model 组合都补进上游 aliases** —— 历史 aliases 已冻结，逐个维护网关前缀扩大上游维护面。常规命名空间由消费端兼容，特殊同价命名向上游补正则。
- **仅自动识别、不做本地映射** —— 无法覆盖内部代号与完全异名。保留可发现、可撤销的完整原名映射。
- **仅本地映射、不自动去前缀** —— 每个常规 provider/model 都需手配。自动兼容与人工补救并存。
- **手动关联插在归一化／正则之前或覆盖已定价模型** —— 隐藏上游被覆盖的时机，超出未定价补救范围。先完成自动链，再应用本地关联；自动规则错误通过上游或自维护 feed 修正。
- **恢复完整本地 pricing.json 私有价目覆盖** —— 重演双价格来源及整模型覆盖丢失复杂规则的问题。只保存名称引用。
- **只去定价总览找目标，或手写映射文件** —— 打断用量上下文，保存与撤销不可发现。未定价处局部选择，全部映射集中管理。
- **沿用旧 rollup，只替换费率和规范名** —— 无法恢复原请求应选的档位与时段。保留原始事实，指纹变化后重建派生聚合。

## Consequences

三个阶段形成完整识别与补救链路，价格唯一来自 feed，自动和手动来源共享历史重算与统计口径。固定 feed 的自动化测试覆盖名称边界、歧义、关联生命周期、历史规则、并发冲突、目录切换、迁移、客户端保存／撤销和草稿编码。全项目 44 个测试文件、872 项测试及后端／客户端构建已通过；[别名覆盖复核](../../testing/2026-10-11-pricing-alias-coverage.md) 确认 v115 的 255 个历史别名及大写变体均恢复原目标。

真实浏览器按 [复核任务](../../testing/2026-10-11-pricing-browser-review.md) 分组验证，未发现已确认产品缺陷；缺少数据或故障条件的 BLOCKED／NOT RUN 项仍不算通过，历史浏览器报告保留当时的实现结论。整体提案转为已实现表示功能阶段已落地，不表示每个浏览器组合场景均已实测。

前缀兼容只能选择上游模型价目作为估算，不证明网关实际同价；人工选择仍可能选错模型。管理页简化为映射和撤销，改绑需重新操作，状态详情不常驻。只存在于旧 aliases、缺少正则覆盖的新名称会未定价，需要上游补规则或本地关联。

正则按快照编译与缓存仍增加读路径成本；上游语法扩展需要显式升级校验。指纹变化后首次历史重建可能变慢，缺源记录不能恢复精确费用。关联保护限于同宿主进程，不承诺跨进程事务隔离；新增存储状态带来异常与迁移维护成本，优先拒绝冲突而非丢失用户选择。

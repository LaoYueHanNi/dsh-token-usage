# DR: 请求列改为一栏文本（表头「请求」，值 `成功/失败`）

Status: implemented

## Problem

「按模型」表的请求列原本用三轨网格呈现成功/失败拆分：左轨成功数（右对齐到斜杠位）、中轨斜杠、右轨失败数（左对齐、错误色）。这层网格有两个代价：表头必须写成三轨的「成功 / 失败」（占两词宽度），而网格的斜杠又要跨行对齐（2026-09-03 的决策为此专门否决过「整格右对齐」）。

用户要两件事：**表头只写「请求」**（把这列的最小占用压下去），以及**数字与表头对齐**。两者在窄列里互相拆台 —— 表头按普通 `th` 右对齐会落到整列右缘，而数值成功数右对齐到斜杠位（列中线偏左），首版就是这样错开一整格的；表头塞进左轨又放不下「请求」二字。

## Decision

**取消三栏结构，这一列就是普通的一栏。** 单元格内容是一段普通行内文本：`132`，或 `132/3`（斜杠分隔，失败数红色、可 hover 看分项）。表头是普通文本「请求」（`stat.requestColumn`），带 `title` 悬停说明「成功/失败」。

因为两者都是同一栏里的普通文本，**对齐由栏自身的规则统一决定** —— 表头与数值共用同一条边，不需要任何轨道、占位或补丁。列宽由「请求」两字与数字的较宽者决定，比「成功 / 失败」窄一截。

失败数仍走原来的 `Tooltip`（`failuresTooltip` 分项、`tabIndex` 可聚焦、`stat.failuresPill` 的无障碍名），只是包在行内而非轨道里；失败数为 0 时不画斜杠、不画 `0`，只印成功数。

## Alternatives considered

- **保留三轨网格，表头塞进左轨右对齐** —— 输在左轨只有列宽的一半，「请求」二字放不下，右对齐会向左溢出到上一列；即使放得下，列也被表头撑到约两倍宽，与压缩的诉求相反。
- **表头与数值统一左对齐** —— 输在风格割裂：入/出/缓/写等列都是右对齐的，一列左对齐像另一张表。
- **三轨 + 伪元素占位（不可见斜杠撑住中轨）** —— 技术上能让表头与所有行的成功数零像素错位，但整栏仍然要为「斜杠中线」留出三轨结构，而用户要的正是**一栏**；占位技巧解决的是一个已经不该存在的问题。
- **固定中轨宽度（8px）** —— 输在「为对齐而写死宽度」：用户明确否掉，宁可紧凑。
- **改用「132 (3)」式、整格右对齐** —— 输在改动值的显示格式，与「值显示逻辑不变」冲突。
- **保留「成功 / 失败」表头** —— 输在它正是要省掉的那份宽度。

## Consequences

- 代价：请求列失去「斜杠跨行成一条线」的视觉（各行斜杠随数字长度浮动），这是 2026-09-03 决策明确要保住的东西 —— 该决策的表头与三轨部分由此**取代**（失败数语义、hover 分项、无失败不画斜杠全部保留）。`RequestsSplitHead` 组件与三轨 CSS（`.split` 及其轨道、`.splitOk`、`.splitFailHead`）随之退役。
- 换来：这列按「请求」两字占宽（比「成功 / 失败」窄一截），表头与数值天然同缘，零对齐补丁；值仍是 `A/B` 斜杠式，语义与可读性不变。

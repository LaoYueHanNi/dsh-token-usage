# DR: 设置明细页签统一大屏形态并移除 compact 密度

Status: implemented

## Problem

设置紧凑明细（[DR: 设置统计区保持两行指标与独立紧凑明细](2026-10-25-settings-compact-dashboard.md)）让四个明细页签与大屏同组件不同形态：项目与模型排行隐藏进度条，相对用量差距失去视觉锚点；会话页签字号与主列脱节；运行开销页签另有一套 11px 紧凑外壳。用户逐页签要求把大屏形态复原到设置区（先项目、再模型、后会话、最后运行开销），四签齐后 compact 密度在设置区再无存在意义。

## Decision

- `UsageRows` 移除 `compact` 密度参数，设置区按项目、按模型、按会话三页签与大屏共用 page 行布局：
  - 项目行：项目名（138px 列 + 悬浮完整路径）、相对 token 进度条、用量·缓存比、费用；
  - 模型行：模型名（定价关联虚线按钮、未定价标记跟随）、相对进度条、用量·缓存比、费用；性能视图沿用 page 形态（无进度条、名称占满、性能数字列），排序控件隐位逻辑不变；
  - 会话行：page 的双行结构（标题 + 费用一行，目录·活动次要行）；会话行在 page 上本无进度条，不新增。
- `OverheadRows` 同步移除 `compact` 参数与 `.compact` 外壳：运行开销页签与大屏同为默认行密度（类别聚合行 + 缩进模型明细 + 合计行），无轻分隔线变体。
- `UsageRows.module.css` 删除全部 `.rowsCompact` 规则（行内规则与 OverheadRows 曾借用的容器限高一起删除——运行开销列表现在与大屏其他明细列表同容器行为）。
- 行内压缩行为沿用 page 规则：进度条 `flex: 1; min-width: 0` 吸收设置区的更窄容器，名称与数字列固定宽不被挤压；容器低于 440px 时仍按既有容器断点折为名称/数字分行，不新增断点。
- 设置工具栏（页签 + 紧凑排序与性能开关控件）不变；数据、排序、过滤与跳转行为零变化。

## Alternatives considered

- **保留 compact 参数、仅设置区不再传** —— 放弃：删除后全仓再无调用者（大屏与测试都不传），留死参数、死 CSS 和一个只有名字存在的密度变体会邀请误用与漂移。
- **运行开销保留紧凑外壳** —— 放弃：用户明确四签统一复原；运行开销的类别行数少，page 密度在设置区不构成空间压力。

## Consequences

- 代价：设置区明细行距与字号变大，纵向高度增加；运行开销展开多模型明细时设置区更长。
- 换来：设置区五个明细页签（项目/模型/会话/供应商/运行开销）与大屏完全同形态，同一组件一套规则，无密度分叉；`UsageRows` 与 `OverheadRows` 各少一个参数，CSS 面收窄；排行相对量与类别开销在设置区可读。

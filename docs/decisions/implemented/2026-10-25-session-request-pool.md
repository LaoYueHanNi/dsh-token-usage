# DR: 会话用量页的实时请求池与请求级缓存三档提示

Status: implemented

## Problem

会话「用量」页签此前只展示结算后的聚合：请求完成、用量记录落盘后，汇总卡、趋势与按模型表才会变化。等待首 token、生成中、失败、取消中的请求完全不可见；单次请求的速度与缓存命中也只能从会话均值反推。用户排查「这一条请求为什么慢 / 缓存为什么没命中」时没有任何单次视角，而设置大屏与模型表的聚合色阶也无法回答单次请求的问题。

## Decision

> [!NOTE]
> 本决策中的顶部请求选择规则已于 2026-10-25 由 [DR: 会话请求面板优先展示范围内的活动请求](2026-10-25-active-request-panel-priority.md) 部分取代。当前在截取 20 条之前优先选择最新启动的等待/生成中请求，其余行仍按开始时间降序；无活动请求时恢复最新请求。

> [!NOTE]
> 本决策中的路由白名单缓存资格策略已于 2026-10-25 由 [DR: 请求缓存提示直接依据已报告数据，不设路由白名单](2026-10-25-cache-hints-from-reported-usage.md) 取代。当前所有路由的有效已报告数据直接参与三档提示，`cache-unknown` 已移除；下文白名单内容仅记录初始策略，不是现行规则。冷启动、切换首条和其他排除规则保持有效。

> [!NOTE]
> 本决策中的请求数值配色已于 2026-10-25 由 [DR: 请求命中率数值与汇总卡共用色阶，标签独立判定](2026-10-25-request-hit-rate-shared-colours.md) 取代。数值当前复用汇总卡四色，不再按诊断档位统一标黄；标签规则保持不变。

- 完成请求只在头部显示「已完成」，不再在页脚重复「请求已结算」；页脚保留费用与缓存读写、进行中/异常结束信息，以及刷新失败时的数据截止时间。
- 请求观察器（`src/request-observe.ts`）在 `llm/stream` waterfall 上注册独立于 `recordAux` 开关的被动透传监听：每次 provider 尝试（每次 waterfall 调用）即池的一行，身份为 `<epoch>:<sessionId>:t<turn>:s<step>:a<序号>`。重试由 dsh-llm-retry 在 agent loop 的 `agent/request-error` 层驱动、loop 在同一 turn/step 内重新派发，故同格第 N 次 waterfall 调用即第 N 次尝试；取消与观察丢失在生成器 `finally` 中按 `signal.aborted` 区分为已取消 / 连接中断；`turn/end` 兜底解析流未观察到的终态。辅助旁路调用（无 sessionId、`session-title`）不进池；压缩调用带 `purpose: 'compaction'` 且归属其会话。
- 每一个会落库的结算来源都被观察器按持久 id 关联回自己的尝试行，合并因此永不产生第二行：`assistant/message` 命名该 turn/step 的完成尝试；`llm/retry`（在 backoff 等待**前**追加，此时格内最新派发即刚失败的尝试）与 `turn/end` error（含策略用尽后的终败）映射到 `failure:<session>:<seq>` 行；`compaction/summary` 经压缩锁窗口（`compaction/start` 持有 per-session 锁至 `end`，窗口内的 summarize 调用即被摘要的那次）映射到 `compaction:<session>:<seq>` 行。
- 合并是**字段级**的：持久行提供持久事实（状态、模型、token 桶、kind），运行侧提供精确的尝试开始顺序与单次时钟。结算事件关联后，写日志前以 `decorateRecord` 附加可选 `attemptTiming`（startedAt、settledAt、firstTokenAt），在 TTL 清理或进程重启后仍按同一尝试的开始顺序和耗时展示。既有 `latencyMs` / `firstTokenLatencyMs` 保持步骤级口径，不改变汇总性能语义；`startedAt` 步骤锚与旧记录结算时间仅作为缺少精确尝试信息时的兼容回退。实时侧缺首字时不拼入步骤级首字，避免跨重试混合时钟。已关联行使用持久 id，日志落盘前后不再次换名。
- 流协议中 `usage` 只在终止 finish 前出现一次，不存在生成中可信 token 计数，因此实时能力恒为 `lifecycle`：运行行只展示生命周期（等待/生成中、服务端锚定已耗时、已确认首字），速度在完成后按共享的 500ms 生成时长门（`settledSpeedOf`，与模型表性能累加器同阈值）服务端结算；不用字符数、chunk 数或会话均值伪造 tok/s。
- `fields=session` 响应新增 `requestDetails`（`src/session-request-details.ts`）：范围过滤在截断前，持久记录与运行态按 `durableRequestId` 原位合并去重（终态不回退、不双记），全量序列上标记冷启动与切换首条（不看 20 条窗口行号），先为顶部保留最新活动请求，再按开始时间降序截取其余记录，共最多 20 条（1 顶部 + 19 历史，仅限展示，不截断日志、汇总或趋势）。无活动请求时直接按开始时间降序。`chip` 与整库 `full` 读取不携带该对象。
- 请求级缓存判断（`src/request-details.ts`）独立于全局色阶：命中率 = cacheRead ÷ (未缓存输入 + cacheRead)，缓存写不入分母；<50% 数值琥珀并在模型右侧贴「缓存过低」标签，50%–80% 仅标黄，≥80% 正常；判断一律用原始精度（49.96% 显示 50.0% 仍属低命中，Tooltip 说明原始值）。缓存读字段缺失即「未报告」，绝不当作 0%。资格证据来自适配器源码语义：仅 `deepseek-official` / `deepseek-account`（llm-deepseek 逐字段透传、自动缓存）为 eligible，其余（pi-ai 适配器把 0 折叠为缺失、部分底层需显式标记）一律 unknown；unknown、冷启动、切换首条、进行中、非成功、压缩、输入不足 64 token 缓存块（仅 eligible 路由按其文档语义推导）、数据无效均排除标签。**路由身份是 provider + 模型**：切换检测在相邻两行都携带 provider 时按 (provider, model) 比较——同名模型换路由（如 official → account）同样是新缓存上下文的首条；任一侧缺 provider（旧行）退回模型级比较，不因身份缺失扩大排除。排除原因以稳定枚举上送，客户端本地化；标签文案为「缓存过低」（原「缓存失效」，按用户反馈更名），Tooltip 声明这是低命中启发式、不代表已证实服务端缓存故障。
- 记录新增可选元数据：`provider`（assistant/message 溯源的路由键，缓存资格证据）、`interrupted`（宿主对**用户中止且已交付部分输出**的确认标记——合并与重载后该行仍显示已取消，绝不改写为连接中断；只有真正缺失终态证据的行才是连接中断）与 `startedAt`（步骤派发时刻，请求行的开始序锚）。可选、向后兼容，旧日志不回填不重写，缺元数据按 unknown 处理不告警。账务、币种、成功/失败计数语义不变。
- 非 abort 的流直接抛错明确记为失败且原样向上传播，用户 abort 仍为取消；`llm/retry` 和 `turn/end` 可以把缺少 finish 的中断观察与真实终败关联。终败只关联当前 turn 最后一个未关联尝试，不把旧 turn 或多个失败行绑定到同一持久 id。
- 排序时间与计费时间分离：已落库行只用账本的 `record.time` 解析时间规则和峰谷费率，不能用开始锚替代；尚无持久结算时不发布预估费用。这样请求池与汇总账本在费率边界仍一致。
- 用量页在「趋势/按模型」与「子会话」之间插入「最新请求」面板（六指标固定顺序：缓存命中、输入、输出、首字、耗时、速度；费用/缓存读/缓存写弱化在底部）与「实时请求」表（11 列固定顺序：来源、状态、时间、模型及标签、缓存命中、输入、输出、首字、耗时、速度、费用）。刷新沿用既有 freshness 防抖；兜底轮询**串行化**——上一次拉取结算后才安排下一次（有活动请求 1 秒、空闲 5 秒、页签隐藏不安排、恢复可见立即刷一次），慢响应永不被下一轮取消；刷新失败仅保留**同一范围**的旧快照并显示数据截止时间（快照按范围隔离：切换范围后新范围的首次失败进入错误态，绝不把上一范围的行当作当前范围展示，旧范围的晚到响应亦被丢弃）。窄屏指标折两行三项，历史行转卡片（标签仍跟模型），表格空间不足时局部横滚不隐列；新请求轻量淡入并尊重 reduced-motion。
- 查询范围与请求缓存身份来自同一即时 scope，只有事件 freshness 做防抖；每次请求捕获自身 scope，范围变化会取消旧请求。所有拉取开始前取消待触发的轮询定时器，进行中恢复可见不再取消同一请求。UI 对齐定稿：150px 会话趋势、状态圆点与矢量警告图标、数字与单位分级、页脚结算状态；历史区域固定上限 196px（窄屏 230/240px）、吸顶表头与局部滚动，不让 19 条历史把子会话挤出页面；按用量面板容器宽度而非整个窗口切换布局；缓存标签通过 `light-dark()` 跟随 DSH 显式主题而不是操作系统主题。已结束但无速度的请求不再显示“待结束后结算”。

## Alternatives considered

- **客户端拼接运行态与持久列表** —— 被放弃：两套异步列表在会话切换、迟到结算与竞态下必然出现重复行或串线；改为服务端单点合并，客户端只渲染快照。
- **结算后整行替换运行行** —— 被放弃：落库行只有结算时刻（排序会倒置开始顺序）与步骤级计时（跨重试的耗时冒充单次速度）；改为字段级合并，开始锚与单次时钟属于运行侧、持久事实属于日志。
- **为「生成中速度」做字符数估算** —— 被放弃：字符数与 chunk 数都不是 token，会话均值不是单次速度，任何伪造都会污染用户对真实性能的判断；诚实显示 — 并注明待结算。
- **把 eligibility 判定做成模型名关键字匹配** —— 被放弃：`包含 deepseek/claude` 式匹配会把无证据的网关路由误标为可告警；按适配器源码语义建立最小白名单，拿不到证据统一 unknown。
- **给所有 provider 套一个最小输入阈值** —— 被放弃：各 provider 缓存粒度与开关语义不同；64 token 块仅来自 DeepSeek 官方语义，只作用于 eligible 路由。
- **切换标记只看模型名** —— 被放弃：同名模型换 provider 路由（official → account）是新缓存上下文，模型级比较会把新路由首条的 0% 误报为缓存失效；路由身份比较 provider + 模型，身份不足退回模型级（旧行为）。
- **固定间隔轮询** —— 被放弃：接口慢于间隔时新轮询不断取消旧轮询，页面永远停在旧快照；改为结算后串行调度。
- **在历史记录中回填冷启动/切换元数据** —— 被放弃：臆造历史数据违反兼容约束；序列排除改由服务端在读取时从全量记录推导，重载后判断一致。

## Consequences

- 代价：插件在 waterfall 上多一层被动包装（不改变流语义但增加一条监听链）；观察器要消费四类结算事件并维护压缩锁窗口才能把每个持久 id 关联回尝试；运行态需要 TTL/上限清理；新记录增加可选的步骤锚与精确尝试时钟，历史缺失信息不臆造；`fields=session` 响应变大（≤20 行明细）；无实时 token 计数意味着「生成中」行的输出与速度必须留白；串行轮询把兜底刷新的节奏绑定在上一次拉取的结算上（慢接口下拉长刷新间隔，而不是并行堆请求）。
- 换来：等待/生成中/失败/取消首次可见，单次速度与单次缓存命中有了可信来源；重试每次尝试独立成行且不双计费；落库前后同一请求只有一行、位置与时钟稳定（重载后依然开始序）；冷启动与切换首条按真实路由身份判定不误报；已确认的用户取消在落库后仍是已取消；旧日志与旧宿主（无 llm 服务时诚实降级 settled-only）行为可预期；全局统计、模型表与设置大屏的语义零改动。

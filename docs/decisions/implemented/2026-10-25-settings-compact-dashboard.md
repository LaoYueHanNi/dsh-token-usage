# DR: 设置统计区保持两行指标与独立紧凑明细

Status: implemented

## Problem

大屏的窄容器响应式规则复用到设置区后，八张指标卡从两行变为四行，占据了过多垂直空间。设置区下方的全宽页签、独占一行的排序、长进度条以及运行开销的最小高度留白也让内容松散，项目名称反而提前截断。设置区与主列页宽度、信息密度不同，不应要求完全一致的布局。

## Decision

- 部分取代 [公共看板与四卡片设计](./2026-10-24-usage-dashboard-isomorphic-board.md) 和 [完整性边界](./2026-10-25-dashboard-aggregation-correctness.md) 中设置区跟随大屏重排指标和复用大屏行密度的约定；数据来源、统计口径、过滤和跳转行为不变。
- 设置 `OverviewBoard compact` 使用八张 `size="sm"` 指标卡，四列、两行固定排列；卡片为 16px 数字、10px 标签、8px/9px 内边距。page 的九轨、五轨、窄屏两列规则只影响 page 指标网格，不能命中设置网格。
- 设置明细单独使用 `detailPanel`：页签与紧凑排序控件位于同一工具栏，窄时允许换行；模型性能开关沿用独立展示模式，激活后排序隐位占位。列表直接跟随工具栏，取消散落的独立排序行。
- `UsageRows compact` 保留同一数据和交互组件，但隐藏装饰性长进度条，把可用宽度让给名称；数字与费用保持右对齐，11px 字号、9px 行内纵向间距，不强设最小高度。列表仍限高滚动，窄行仍按名称与数字分行。
- `OverheadRows compact` 为类别添加轻分隔线，类别名强调，模型明细通过缩进和竖线表达层级；去掉最小高度空白，让合计紧随实际内容。page 仍使用原始行密度和布局，不增加设置区外壳。
- CSS 解析回归测试约束：任何指标容器断点均不得覆盖 `.metricGridCompact` 的四列规则；组件测试同时约束小卡片、统一工具栏和紧凑列表。

## Alternatives considered

- **设置区也降为两列指标** —— 虽然沿用 page 响应式最方便，但会变成四行，违背设置区两行读完指标的明确要求；改为缩小卡片。
- **继续沿用大屏的进度条和独立排序行** —— 设置区的空间有限，长条挤占名称，单独排序行与大片空白又拉长页面；设置区只保留紧凑数字列表。
- **复制一套设置页组件和数据流** —— 会使过滤、定价、性能与会话跳转实现漂移；保留共享组件的紧凑展示参数，仅分开布局。

## Consequences

- 代价：共享卡片和列表增加设置专用展示参数；设置区不再展示相对排行条，不能与大屏逐像素对应。
- 换来：八张指标固定两行，下方明细更紧凑、名称空间更充足；主列大屏保留原布局，统计与交互仍为同一实现。

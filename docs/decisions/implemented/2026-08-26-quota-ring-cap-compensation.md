# DR: 配额环图标采用圆帽 dash 补偿渲染，区分"满环"与"近满"

Status: implemented

## Problem

输入栏配额按钮的触发图标（`src/client/QuotaButton.tsx` 的 `QuotaGlyph`）是一个 14px 环形图：viewBox 14、r=5.5、stroke-width 2、`strokeDasharray` 保留 3 位小数，填充弧表示最细粒度配额窗口的**剩余比例**。需求：剩余 99% 与 100% 必须在图标上可分辨（"这个窗口到底用没用过"）。

2026-08-26 的实证调查结论（真实浏览器按 `QuotaGlyph` 精确参数栅格化后做像素对比，14px @1× 与 2×/3× 分辨率）：

- **数值精度不是瓶颈**：dasharray 0.001 单位 ≈ 周长的 0.0029%（1/34000），计算链（`quotaIconFillShare` 浮点直传）无取整损失。
- **round 线帽吞缺口**：每端延伸 ½ 线宽，两端共 2 单位 ≈ 周长 34.5575 的 5.8%。中心线缺口在剩余 ≥ 94.21% 时被完全覆盖，**99% 与 100% 渲染结果 0 差异像素**；剩余 92~96% 区间还会在线帽相切处出现读作脏点的透镜伪影（maxΔ99）。
- **视觉可辨门槛约 7.5% 已用**（剩余 92% 以下缺口才开始可辨）；圆帽和线宽 2px 的抗锯齿是主因，与 DPI 无关（2×/3× 栅格化下 99% 仍不可辨）。
- **butt 帽实测不够**：可见门槛降到 ~3% 已用，但 99%、98% 与 100% 仍是 0 差异像素；且宿主 ContextMeter 原版（`@deepseek-ai/dsh-client-ui-conversation` 的 `.JObwrW_fill`）用的是 round，改成 butt 会偏离该图标家族样式。
- 现有测试（`tests/quota-button.client.spec.tsx`）只断言 dasharray 字符串，从未覆盖视觉可辨性。

## Decision

`QuotaGlyph` 对 dash 长度做**帽补偿**：dash = share·C − `RING_CAP_REACH`（常量 2 = 线帽总延伸），使"弧 + 圆帽"的实际涂色范围恰好等于名义比例，圆帽只画在弧内、不再吃掉缺口。三条路径：

- **share = 1**：dash 取整个周长 + butt 帽（沿用原有特判，硬性要求——补偿后的圆帽只在一点相切，边缘会留 2px 蝶形缺口，100% 会看起来像 98%）；
- **名义弧长 ≤ 2**（剩余 <5.8%）：不补偿、保留原始 nub（dash ≤ 0 会什么都画不出来）；
- **其余**：dash = 名义弧长 − 2，round 帽。

生效原理是**蝶形缺口**：圆帽圆盘以弧中线为圆心，越靠环的内外边缘沿弧延伸越小（按 √(1−d²) 衰减，到环边缘归零）。补偿后 12 点缺口呈蝶形——中线处仍为 (1−share)·C（保持线性），环内外边缘处张至 (1−share)·C + 2 ≥ 2px，**任何非零使用量必留下可见的边缘缺口**，"100% 密封 ↔ 99% 有痕"的二分成立。实测（14px @1×，与 100% 满环对比的差异像素）：99% → 12px（maxΔ71，可分辨）、98% → 15px、95% → 15px（maxΔ174）；原渲染下 99%~97% 全部 0。观感评估（视觉模型对比渲染图）：蝶形缺口被读作"有意的刻度"而非渲染瑕疵，随剩余下降自然过渡为普通圆帽缺口。

`tests/quota-button.client.spec.tsx` 同步更新近满（0.99·C − 2）、极小（不补偿）、恰好满（整周长 + butt）三条路径的断言。

## Alternatives considered

- **维持现状（"几乎满"视为"满"）** —— 语义上可辩护，但明确存在"区分 99% 与 100%"的需求，且 94.2% 相切伪影会继续存在。
- **butt 帽** —— 实测 99%/98% 与 100% 仍 0 差异像素，达不到目标；还偏离 ContextMeter 家族的 round 样式。
- **√已用 缩放映射**（缺口 ∝ √已用，1% 已用 → 3.5px 缺口） —— 唯一能提供近满区**连续**细刻度的方案，但环填充不再线性对应剩余率、与面板进度条（线性）矛盾、偏离"剩余=填充"的信号灯语言；帽补偿已满足"满/未满"二分需求。
- **满环特殊标记**（100% 时中心加小圆点表"全新窗口"） —— 只标记单一状态，信息量低于帽补偿，且多一个图形状态。
- **加大环尺寸** —— 1% 差异要看清约需 50px 环，输入栏 28×28 按钮放不下。
- **近满过渡色阶** —— 颜色通道已被红/黄/绿信号灯占用，叠加细粒度色阶会让两个视觉通道打架。

## Consequences

- 代价：蝶形缺口是新形状，14px 下的评估基于绿色前景/白色背景，未在其他主题色、深色模式或其他字号下逐一验证；相邻百分比（99 vs 98）仍不可分（线性 0.35px/步，本方案给的是"满/未满"二分 + 近满粗刻度，连续细刻度让位给 √ 映射的可能性）；剩余 ~5.8% 处补偿段与 nub 段存在一个预计无感的渲染不连续点。
- 换来：14px 渲染下 99% 与 100% 像素级可区分（12 差异像素 vs 原来的 0）；任意非零使用量在环上必留可见痕迹；94.2% 相切伪影随补偿一并消失；编码保持线性、圆帽观感与 ContextMeter 家族样式原样保留。

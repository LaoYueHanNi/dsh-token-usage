# DR: 子会话表限高 15 行，点击（聚焦）后才在列表内滚动

Status: implemented

## Problem

用量视图的「子会话（N）」表此前全量渲染、纵向不设上限：一张会话的子会话一多（实测 59 个），整张 dashboard 被拉长几千像素，趋势、按模型、请求池都被推远，滚到底才能看到表下注脚。

第一版把它改成"限高 15 行 + 壳内滚动（overflow: auto + overscroll-behavior: contain）"，实测暴露第二个问题：鼠标停在子会话表上时滚轮被壳吃掉，整页滚不动，只有把指针移到表格左右两侧的窄缝才能滚动页面——嵌套滚动区默认劫持滚轮，比页面变长更难受。第二版试过"15 行预览 + 展开按钮 + 提示文案"，又被明确否决：不要多加控件，要的是"点一下这块区域，滚动才触发"。

## Decision

src/client 两处改动，用浏览器自带的焦点语义实现"点击这块才滚"，不新增任何按钮或提示文案：

- **默认只露 15 行、滚轮归页面**：`UsageView.module.css` 的 `.subagentsWrap` 设 `max-height: calc(26px × 16)`（16 = 1 行表头 + 15 行数据）与 `overflow: hidden`。表格仍全量渲染，但壳不可滚动，指针悬停时滚轮事件直接落到页面上——这正是"整页能滚"的来源。
- **点击（或 Tab）进入列表后接管滚轮**：容器在 `UsageView.tsx` 里带 `tabIndex={0}`，点击表格任意位置（行内标题按钮之外的区域也算，浏览器把焦点交给最近的 tabindex 祖先）或按 Tab 进入，都会让焦点落进列表；CSS 用 `.subagentsWrap:focus-within { overflow: auto }` 把它变成滚动区。此时滚动条出现（`.subagentsWrap:focus-within::-webkit-scrollbar-thumb` 给它 12% 的可见 thumb），滚动时加深到 22%（`.scrolling` 仍由 `onScroll` 直接改 classList，800ms 后移除）——滚动条本身就是"已接管"的状态提示，不需要文案。
- **焦点离开即交还页面**：点击页面其他位置或其他控件，浏览器把焦点移走，`:focus-within` 失效，壳回到 `overflow: hidden`，滚轮又归页面。键盘用户可以 Tab 进入列表后用方向键滚，Esc/点击别处退出。
- **滚到两端会链回页面**：激活态不设 `overscroll-behavior: contain`，列表滚到头后继续滚是页面滚动，不会把人困在壳里。
- **行高固定让封顶精确**：表头行与数据行统一 `height: var(--subagents-row-height)`（26px），`border-collapse: collapse` 下 `tr` 的高度按设定值生效（实测 26px，含边框与单元格 padding），因此 15 行上限是精确的而非"约 15 行"；长标题在单元格内省略（原有 `.childLink` / `.modelCell` 的 ellipsis），不换行、不撑高。裁切线恰好落在行边界上。
- **表头粘性 + 渐隐滚动条**：展开态下 `.subagentsWrap .table th` 有 `position: sticky; top: 0; z-index: 1` 与不透明底色（`--dsw-alias-bg-base` 回退 `--dsw-alias-bg-layer-1`）；滚动条沿用请求池历史表的语法（8px、无轨道、无箭头按钮、thumb 空闲透明）。
- 列数、列宽、横向滚动行为不变（沿用 `.table` 的 `min-width: 480px`）；无子会话时仍是纯文本，不渲染壳。容器带 `role="region"` + `aria-label`（词典键 `view.subagents.scroll`：「子会话列表，点击后可在此滚动」），给屏幕阅读器说明可聚焦与可滚动的原因。

## Alternatives considered

- **默认就壳内滚动（第一版实现）** —— 限高与滚动条到位，但嵌套滚动区默认吃掉整页滚轮，只有侧边窄缝还能滚页面；实测反馈直接否决。
- **15 行预览 + 「展开全部」按钮 + 提示文案（第二版实现）** —— 功能正确、可发现性好，但用户明确否决：不要为滚动这件事多造一个控件和一行说明，要的是"点这块区域就能滚"的直接手感。已回退，代码里不留这个分支。
- **JS 点击激活 + 全局 pointerdown 取消激活** —— 与 `:focus-within` 等价，但要自己维护激活状态、监听 document 外部点击、处理与 drill-in 点击的先后；焦点语义浏览器已经免费提供，键盘用户也天然可用，没有必要重现一遍。
- **照抄按模型表的固定像素上限（420px）** —— [DR: 按模型表格改为内部滚动壳 + 粘性表头](../implemented/2026-08-30-bymodel-table-sticky-scroll.md) 的做法对"约 13 行"够用，但本次要求是"最多 15 个"：固定像素会随字体/标题宽度把 15 行裁成 14.5 行，或露出第 16 行。
- **JS 测量行高后动态设 max-height** —— ResizeObserver + 首行测量在任意字体下都能精确，但多一个观测器与重排路径，限高值随缩放跳变，而固定行高已经给出确定结果，收益不足。
- **分页 / 虚拟化** —— 子会话数量是几十量级，分页打断浏览、引入页状态，虚拟化为时过早。
- **只截断不提供任何滚动入口** —— 15 行之后的行将完全不可达，无法核对全量；点击激活保留了这个入口。

## Consequences

- 换来：悬停不劫持滚轮，整页滚动在表格上方照常；点击/聚焦后列表在固定高度内滚动、表头恒在视口；焦点离开自动恢复页面滚动；不新增按钮与提示文案；键盘用户可用 Tab + 方向键。
- 代价：未激活时第 16 行以后不可见（只能靠标题里的总数知道还有更多，激活后滚动可见）；激活时出现 8px 滚动条，表格列宽有轻微变化；行为全部落在 CSS 的 `:focus-within` 上，React 层没有可断言的状态，jsdom 单测只能锁住"容器可聚焦 + 表格在容器内"的结构，视觉行为需在真机确认；"15"与 26px 是 CSS 常量，未做成设置项。

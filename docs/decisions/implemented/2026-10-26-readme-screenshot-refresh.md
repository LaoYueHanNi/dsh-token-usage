# DR: README 与市场截图随用量大屏改版整体刷新

Status: implemented

## Problem

插件在 0.4.x 期间完成了一轮界面改版：侧栏新增常驻「Token 用量」入口并打开全宽用量大屏（设置区与大屏的明细维度：项目 / 模型 / 会话 / 供应商 / 运行开销）、会话用量页签新增实时请求池与分时 / 累计趋势、过滤条新增「定价表」总览弹窗（模型别名关联按钮打开的独立弹窗）、请求数卡新增失败与开销徽章。仓库根 `screenshots.json` 声明的市场截图清单（[DR: 声明插件市场截图清单](2026-08-28-market-screenshots.md)）与两份 README 仍指向改版前的界面：首图是旧统计页、功能列表描述的是旧语义、把配置卡的入口与统计页的入口混写成了同一个「设置 → 插件 → Token 用量」层级，而 `model-price_zh.png` 是旧界面里叠加在设置页上的整屏截图——里面有真实数据目录、侧栏工作区与会话标题、账号名。

截图素材来自用户真实浏览器的 dsh Web 实例（含真实用量数据与真实会话），直接落库会泄露隐私。

## Decision

- **README 重写**：`README.md` 与 `README.zh.md` 首图换成用量大屏；导语改述「侧栏入口大屏 + 设置五页签」两处入口；功能列表按新语义重写——实时记录的辅助请求归属规则（有宿主证据归属会话的计入该会话，其余全局按类别拆出）、请求数卡的失败 / 开销徽章、五页签明细、大屏五看板与常驻侧边栏入口、会话页签的分时 / 累计趋势、实时请求池、定价表弹窗（模型别名关联按钮打开的独立弹窗）。新增两张配图：`docs/images/settings-usage_zh.png`（设置内 Token 用量页）与 `docs/images/pricing-table_zh.png`（定价表总览弹窗），英文版对应 `settings-usage.png` / `pricing-table.png`。
- **打码用 DOM 文本替换，不做图像涂抹**：通过浏览器 `evaluate` + `TreeWalker` 遍历文本节点，就地替换后再截图。数据目录 `D:\document\dsh-token-usage` → `~/.dsh/token-usage`（正则必须写 `/[A-Za-z]:\\[^\s]*/g`，即要求冒号后紧跟反斜杠，否则会误伤英文文案 `Data directory:` 的结尾字母）；主会话标题、子会话表里的各条子会话标题与用户名「忆到江南时」→ `••••••`。图像涂抹会留下涂抹痕迹且无法保证覆盖到位，DOM 替换产出的图与真实界面完全一致。
- **侧边栏靠裁剪去除**：大屏与会话页原图含工作区列表与会话列表，直接整块裁掉（大屏裁剪框 `(630,0,1640,1300)`、会话页 `(350,20,2000,1250)`）；设置页与定价表用元素级截图，无需裁剪。裁剪脚本 `scripts/crop-shots.ps1` 保留在仓库里，改为参数化（`-In`/`-Out`/`-Rect` 单张处理，或 `-Jobs` 批量 JSON 任务表），后续再更新截图可直接复用。
- **市场截图清单同步**：第 3 张由 `model-price_zh.png` 换成 `pricing-table_zh.png`——单模型价格表是一条约 791×180 的窄条，作为市场轮播第三屏展示力不足，定价表总览弹窗（941×868）更能说明定价能力。`model-price_zh.png` 与 `model-price.png` 本身仍然更新为单模型价格表的元素级截图（中文 / 英文各一张），不删图。
- **设置路径按实际界面修正**：README 里指向**统计页**的入口写作 `Settings → Token Usage` / `设置 → Token 用量`——设置侧栏里「Token 用量」是与「内置插件」「插件市场」并列的顶级项（同一次提交的截图 `docs/images/settings-usage_zh.png` 左侧栏可见这两个顶级项），它渲染的是只读统计页：页内只显示当前数据目录一行（`TokenUsageSection.tsx` 的 `dataDir` 文本），其余明细在页签里。需要**改**的配置项——数据目录、定价区域、常驻侧边栏——在宿主插件页里本插件的**配置卡**上（`plugins.bundle.config` 槽位，键为包名 `@laoyuehanni/dsh-token-usage`，渲染 `TokenUsageCard`），与统计页不是同一个地方。0.4.13 版 README 的「设置 → 插件 → Token 用量」指的正是这张配置卡，统计页则从来不是这一级。
- **界面语言随截图切换**：中文截图在中文界面采集，英文截图把 dsh 界面语言切到 English 后采集，采集完切回中文；英文界面下模型名按钮的 `aria-label` 是 `View rates for <模型>`，中文界面是 `查看 <模型> 定价`。

## Alternatives considered

- **图像涂抹打码（矩形 / 马赛克）** —— 放弃：涂抹痕迹明显、边角容易漏出字符，且同一张图反复涂抹后无法验证是否全覆盖；DOM 文本替换既能保证替换干净，也能让截图与真实界面完全一致。
- **保留旧的 `model-price_zh.png` 整屏截图** —— 放弃：那张图里带着旧设置页的真实数据目录、侧栏会话列表与账号名，与本轮「无隐私」的截图标准冲突；重拍成元素级截图后既干净又能只讲价格表本身。
- **市场清单里换成英文界面截图** —— 放弃：沿用既有约定，dsh-market 的界面与主要用户群是中文；中英文两套 README 各自的配图已各自成对，英文版图仍保留在仓库中。
- **用 Python 处理图片（裁剪 / 打码）** —— 放弃：本机 Python 无写文件权限，任何图片处理脚本一落盘就 PermissionError；改用 PowerShell `System.Drawing` 完成裁剪。

## Consequences

- 代价：README 与截图必须在每次界面改版后重新采集与打码，是持续成本；打码规则（哪些文本要替换）靠人工约定，没有自动化校验——本轮就漏过一次：主会话标题已打码，会话页「子会话」表里的子会话标题却仍在图上，需靠逐张复核才发现。
- 换来：README 描述与实际界面一致，读者按图索骥能对上；市场截图清单与 README 指向同一批新图；全部图片不再包含真实路径、账号、会话标题等隐私信息。

# DR: 请求缓存提示直接依据已报告数据，不设路由白名单

Status: implemented

## Problem

实时请求池原先仅允许 DeepSeek 官方路由触发缓存提示。GLM、自定义网关及缺少 provider 元数据的旧记录，即使已有有效命中率，也只展示中性数值，并常驻“无法确认该路由的缓存资格”说明。用户明确要求移除此限制，直接展示缓存表现。

## Decision

> [!NOTE]
> 本决策中的请求数值配色已于 2026-10-25 由 [DR: 请求命中率数值与汇总卡共用色阶，标签独立判定](2026-10-25-request-hit-rate-shared-colours.md) 取代。当前数值复用汇总卡四色，标签阈值与本决策的数据及排除规则不变。

- 部分取代 [实时请求池决策](2026-10-25-session-request-pool.md) 中按 provider 白名单判断缓存资格的策略，其他请求池规则不变。
- 所有路由及 provider 缺失的旧记录，只要已完成且已报告有效输入和缓存读计数，就直接套用请求级三档：低于 50% 标黄并贴模型右侧“缓存过低”，50% 至低于 80% 仅标黄，80% 及以上正常。标签仍是低命中提示，不是服务端故障结论。
- 删除 `cache-unknown` 排除原因及对应常驻说明；保留 wire 的 eligibility 字段，用于表示有效已报告数据是否可评估，不再表示 provider 白名单。
- 保留冷启动、切换模型或路由后的首条、进行中、非成功、压缩、未报告、无效数据等排除；缺失缓存读不当作 0。DeepSeek 官方路由的 64 token 块下限只作用于已知路由，不扩展给其他 provider。

## Alternatives considered

- **保留白名单，只隐藏说明** —— 放弃：只去掉文案仍会使第三方路由的有效低命中数据无法触发用户确认的标签。
- **所有路由缺失缓存读一律视为 0** —— 放弃：缺失可能来自服务商未报告或适配器折叠，不能当作真实未命中。

## Consequences

- 换来：第三方路由和旧记录均可直接展示请求级缓存表现，卡片不再常驻路由资格解释。
- 代价：无法确认每个第三方的缓存开启条件，低命中标签可能包含合法的低命中场景；保留排除规则与启发式说明，但不再以路由身份屏蔽可见数据。

# DR: 请求命中率数值与汇总卡共用色阶，标签独立判定

Status: implemented

## Problem

最新请求与历史列表原先按请求诊断档位标黄，正常值不着色，与上方汇总卡的红、橙黄、黄绿、绿色阶不一致。用户要求同一命中率在上下区域使用相同配色，并随数值变化。

## Decision

- 部分取代 [请求池决策](2026-10-25-session-request-pool.md) 和 [已报告数据缓存提示决策](2026-10-25-cache-hints-from-reported-usage.md) 中的请求数值配色策略；数据来源、标签阈值和排除逻辑保持不变。
- 最新请求与历史列表直接复用汇总卡的 `bandOf` 和 `bandClassOf`：低于 60% 红色、60% 至低于 80% 橙黄、80% 至低于 95% 黄绿、95% 及以上绿色。阈值依据原始值，命中率文本仍保留请求级格式化精度。
- 数值颜色只表达已报告命中率的大小，不表达缓存故障。即使冷启动等原因排除了标签，已有有效数值仍按统一色阶显示；缺失值保持中性占位，不视为 0。普通有效命中率只显示数值，不为解释色阶额外提供悬浮提示；低于 50% 的“缓存过低”标签和排除原因仍保留各自说明。
- “缓存过低”标签独立使用既有低于 50% 阈值及所有排除规则，标签自身的琥珀配色不变。移除普通低命中率为了说明“颜色与上方卡片一致”的多余悬浮提示。

## Alternatives considered

- **复制汇总卡的阈值和 CSS 到请求组件** —— 放弃：重复实现会使后续调整再次分叉，直接复用已有分类函数和样式映射。
- **数值颜色跟随标签是否适用** —— 放弃：冷启动和普通请求即使命中率相同也会显示不同颜色，不符合用户要求。排除原因仍通过悬浮提示解释。

## Consequences

- 换来：上下区域同值同色，最新面板与历史列表同步使用共享色阶。
- 代价：50% 至低于 60% 的数值是红色但没有缓存失效标签，冷启动低命中也可能是红色；数值颜色与诊断标签是两个独立维度，不再混用。

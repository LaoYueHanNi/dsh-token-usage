# DR: 按模型表定价入口改为模型名本身可点

Status: implemented

## Problem

按模型表模型列固定 150px（防止自动布局把剩余宽度全灌进最长名字列）。行内「定价」小按钮跟在 id 后面：已定价几乎每行都有，占约 36px，名字被截成 `deepseek-v4.1-fl…`，按钮又因 id 长短不齐无法成列。未定价徽标同理但出现少，不是主痛。定价总览已经是「点模型行开详情」（见 [定价表总览](2026-09-05-pricing-table-overview.md)），用量表却另做一套徽章。

## Decision

已定价行的模型名就是定价入口：`<button>` 看起来像普通单元格文字，`aria-label` 仍是「查看 {model} 定价」，hover 用与筛选行「定价表」相同的 `--dsw-alias-link-primary`。未定价行仍是纯文字 + 「未定价」徽标（费用列 `—`、页顶警告条照旧）。行内「定价」徽章删除。筛选行「定价表」总览入口不动。

## Alternatives considered

- **徽章右对齐钉死** —— 按钮齐列，但 150px 里永远扣掉一块，长 id 照样截断。输了：占空间的根因没解。
- **点费用数字** —— 费用列语义贴近计价，但已定价行几乎都有费用，热区离模型身份远，且 `¥0.00` 的已定价行（免费窗口）不像可点。输了：身份列才是「看这个模型的价」。
- **去掉行内入口，只走定价表** —— 零 chrome，但看当前筛选里某个模型的价要打开总览再搜，比原来多一步。输了：快捷入口有价值，错的是形态。
- **hover 才出现图标/按钮** —— 默认态干净，但发现性差，表格里也不打算上悬停教学。输了：名字常显可点、hover 变色已经够轻。

## Consequences

- 换来：已定价 id 左对齐、列宽全给名字；入口与定价总览「点模型看价」同一套；`aria-label` 不变，既有打开弹窗的测试不用改选择器。
- 代价：静止时看不出名字可点（有意：避免整表读成链接列表），靠 hover 变色与指针；未定价行仍带徽标，与已定价行视觉不完全齐——未定价是例外状态，保留行内警告。

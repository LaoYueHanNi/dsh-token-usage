# DR: 按模型表格改为内部滚动壳 + 粘性表头

Status: implemented

## Problem

「按模型」表格与定价弹窗的价目表此前的滚动壳只管横向（overflow-x，防止窄面板挤压单元格），纵向全量渲染、跟随设置面板整体滚动：模型一多页面极长，滚到下方列标题早已滚出视口，长表不可读；价目表同理（timeRules 多时行数可观）。需求确认按"内部滚动 + 粘性表头"落地，不做分页。

## Decision

src/client/TokenUsageSection.module.css 一处样式收敛，两个表格（按模型表、定价弹窗价目表）共享同一壳：

- .tableWrap 由 overflow-x: auto 改为 overflow: auto + max-height: 420px —— 纵向超出即壳内滚动，约可见 13 行数据；窄面板横向行为不变。
- .table th 增加 position: sticky; top: 0; z-index: 1 与不透明底色 --dsw-alias-bg-layer-2 —— 滚过的行从表头下方穿过，列标题始终可见；明暗主题由 token 自适应。
- 定价弹窗沿用同一壳：dialog 自身限高（100vh - 48px）与 420px 表壳叠加后，常规高度下 dialog 不再出现纵向滚动，滚动收敛在表壳内，表头同样粘性。

## Alternatives considered

- **分页（每页 N 行 + 翻页控件）** —— 打断浏览（看全量分布需逐页翻），引入页状态与与筛选状态的组合管理，当前数据规模（模型数=本地出现过的模型名，几十量级）不值得。
- **Top-N + 展开全部** —— 排序已按请求数降序，长尾天然靠后；但展开控件与"全部渲染"的滚动体验差别不大，还要多一个交互态。
- **虚拟化列表** —— 上千行才值得，为此引入窗口化逻辑或依赖，远超当前规模需要。

## Consequences

- 换来：长表被限高在面板内、表头恒在视口；两个表格行为一致；纯 CSS 变更，结构零改动。
- 代价：面板内出现独立滚动区（滚轮停在表格上时被壳吃掉，不再滚动整页）；420px 为固定值，极小视口下壳占比偏高；粘性表头依赖不透明底色，未来若把表头改成透明设计需同步处理。

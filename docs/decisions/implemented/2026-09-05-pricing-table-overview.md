# DR: 设置页新增完整定价表总览（独立路由 + 家族排序弹窗）

Status: implemented

## Problem

云端定价表（实测镜像 166 个模型）在 UI 上不可浏览：现有「定价」弹窗只能看统计筛选范围内出现过的模型的价，其余模型完全不可见。定价表的形状信息（modelId 与别名的关系）在 `cloudToTable` 展平后也丢了。整表数据其实已随 whole stats 响应下发（`attachCosts` 把 merged `PricingTable` 塞进 `pricing` 字段），只是没有 UI 消费它。语义上还有一层错位：按模型表是受筛选约束的用量视图，定价总览不受筛选约束——它需要独立的入口与数据通道，而不是搭在用量响应上。

## Decision

**后端：`/token-usage/pricing` exact 路由**（`src/stats-route.ts` 的 `createPricingRoute`，与 migration/dir-guard 路由同模板：same-origin 校验、`no-store`、405/403/500 分支），返回**模型行**形状而非 flat `PricingTable`：`models: [{ modelId, aliases, family?, rules: ModelRates }]` + 展示用 `currency`/`usdExchangeRate`（region thunk 同 stats 路由）。`src/pricing.ts` 新增 `readPricingOverview` 保留 feed 的 models 数组形状直出（`readPricingTable` 的合并语义不受影响）；`coerceCloudPricing` 透传上游 `family` 字段（`CloudPricingModel.family?: string`，非字符串/空串丢弃）。总览只呈现云端镜像：本地 `pricing.json` 手工覆盖机制已废弃（见 [DR 2026-09-05](2026-09-05-abolish-manual-pricing-json.md)），不读它、不呈现它。不用 flat 表的原因：`cloudToTable` 把别名展开成独立键，总览里同一模型会重复成多行同价行；保留形状让前端每模型一行，别名不展示、但仍作搜索维度（命中别名即浮出该模型）。无元信息（version/updatedAt/来源/同步时间）。

**前端：入口**在筛选行（FilterBar）行尾、模型菜单之后：行内三个控件是"选择器"（决定下方数据看什么），行尾入口是"动作"（打开与筛选无关的视图），不进筛选语法。形态是**蓝色文字标签**（`.pricingLink`）：`--dsw-alias-link-primary`（fallback `label-primary`）、无边框无底、28px 点击区（padding 4px 8px + 13px/20px）、hover 显 `--dsw-interactive-bg-hover` 圆角灰底（`dialogClose` 手法）。文案用独立 locale key（中文「定价表」/ 英文 "Pricing"），不复用单模型的 `pricing.viewShort`「定价」。

**前端：总览弹窗**（`src/client/PricingOverviewDialog.tsx`）。native `<dialog>`（PricingDialog 模式：showModal、Esc/背板关闭、焦点困住、top layer；背板点击关闭以**按下落点守卫**——click 在按下/释放目标的最近共同祖先上派发，从输入框拖选文本到弹窗外松开时该祖先恰是 dialog 元素（top layer 外的一切落点都解析为 dialog），仅按 click target 判定会把拖选释放误判为背板点击而关掉弹窗，故要求 mousedown 也落在背板上才关），宽度 `min(720px, calc(100vw - 48px))`。按需 fetch `/token-usage/pricing`（不带任何 query 参数——与筛选解耦，筛选变化不影响已打开的总览；fetch 失败与空镜像统一提示「模型定价获取失败」+ 重试）。结构：搜索框（弹窗顶部固定区）+ **平铺模型长表**（`table-layout: fixed` + 模型列 40%，列宽由表头定义、不随内容或搜索变化；列头 sticky；滚动壳固定 `height: min(60vh, 520px)`）；每行 = 模型名 + 生效价 4 列（入/出/缓/写，口径见下文「生效价主行」），货币跟随页面视图（`currencyViewOf`，USD 换算并在表下标注）。

**平铺排序、已用标记与家族序**。总览是单层平铺表：所有模型行直接列出、不分组不折叠，默认按 feed 每模型行自带的 `family` 字段排序（家族字母序，家族内 modelId 字母序，缺失落 `other`）——上游权威分类直出、前端零映射表零推断，家族只驱动排序与搜索，不驱动任何 UI 结构，同族模型天然相邻。搜索（modelId/别名/家族名，大小写不敏感子串）过滤行并保持排序。当前筛选 `byModel` 中出现过的模型行加 10px「已用」小徽标（规格同 `unpricedTag`、中性配色；快照在打开瞬间取定，`showModal` 期间 backdrop 盖住筛选行、筛选不可能变化）。点击模型行 → **二级弹窗**展示该模型完整价格表（复用 `PricingDialog`，native showModal 天然层叠：总览在下、详情在上），关闭回到总览；因详情是总览的 DOM 子元素、React 会模拟 close 事件的传播，总览的 `onClose` 以事件 target 守卫，只有总览自身的 close 才收起总览。

**前端结构**：`PricingDialog`/`ModelPriceTable` 从 `TokenUsageSection.tsx` 搬出为叶子模块 `src/client/PricingDialog.tsx`（+ `PricingDialog.module.css`，仿 `StatCard.tsx` 先例），byModel 表照旧用 TokenUsageSection.module.css 的同名类（CSS Modules 哈希隔离）。

**模拟计费（带单位 token 输入框 + 案例填充 + 费用列）**。搜索框下方一行**四个 token 输入框**（输入/缓存读/输出/缓存写），每框 = 数字 × 所选 **K/M/B 单位**段选（切换按倍率换算数字、token 总量不变：98M 切 K 读 98000；非法/负数读 0），其下一行**预设案例按钮**（常量数组 `SIM_SCENARIOS`，按钮命名「案例N」、悬停 title 显示画像「输入 {tokens}（缓存 {pct}%）/ 输出 {tokens}」——加案例只改数组一条目）点击把四值以**精简形态**（按数量级选单位：98M、457K，不足 1K 落 K 档小数）回填输入框；打开时预填第一个案例（打开即有金额可比），案例按钮按下态**精确匹配**当前 token 总量——手动改数或换单位（总量不变）均按数据判定，改数即取消按下、点按钮恢复。表格第 6 列「模拟费用」= 输入框 token 桶 × 该模型**主行（生效价，见下段）四价**（缓存缺价回落入价，与后端 `costOf` 同式；client 侧另实现因 pricing.ts 在 node 半区），`formatCost` 随页面货币显示。列头**三态循环排序**：默认家族序 → 费用降序 → 费用升序 → 回默认家族序（JS 稳定排序：同价行保持家族序）；排序与搜索口径 = **主行费用**（生效价）——命中规则的模型以规则价参与排序（如 deepseek-v4-pro 在降价期内按 ¥3/¥6 而非根价 ¥4.5/¥13.5）；方向指引常显不消失——默认态淡显双向 ⇅（提示该列可点、未激活），降序 ▾ / 升序 ▴ 正常色。搜索过滤不干扰排序、排序不干扰搜索。

**桶区单行扁平胶囊布局**。12 件控件（4 × {label, 数字输入, K/M/B}）排成**一条单行胶囊**（`.buckets`）：整组共享一条边框/圆角/底色，4 段之间 1px 接缝分节（`border-left`），每段 label + input + KMB 横排三件套——朴素摆法都不成立：每桶两行块（label-on-top）整组两行控件高、4 重 chrome 又宽又碎；每桶单行独立桶并排则塞下三件套需 `min-width: 200px`，720px 弹窗下 4 × 200 + 3 × 6 = 818px 必然 wrap。胶囊内 `flex-wrap: nowrap` + 每段 `min-width: 0`：窄弹窗下由 amount input 吸收压缩量，label 与 unit 保持自然宽度不折行。输入框不画自身边框底色（胶囊即 chrome），带**常驻 inset 轮廓**（可编辑区轮廓若只在聚焦时出现，未点开前读作空白槽），focus 仅叠加底色；number **spinner 常驻**（`padding-right: 18px` 给 Chromium 原生 spinner 画布 + `::-webkit-*` 伪元素 `opacity: 1` 覆盖 UA 的 hover-gated 显隐——只调 padding 则容器 0 宽、只调 opacity 则被 UA 规则隐藏，缺一不可），与 K/M/B 互补（段选跨数量级、spinner 数量级内微调）；K/M/B 选中态对齐 `UsageView.module.css` 分段控件（`.segActive`）的既有模式——16% `label-primary` 混合底（`color-mix`，深浅主题都抬升）+ 主色文字 + 600 字重。

**生效价主行与特殊行展开**。定价行是**生效价口径**：主行 = 当前生效世界的默认价——当前日期落在某条时间规则生效窗内（日期范围命中、规则互斥最多 1 条）时主行直接取该规则的默认价，否则取模型根 base；主行裸价格、不带规则名标注（从简）。判定以弹窗打开瞬间的当前时间取定，会话内稳定。主行之外若存在**特殊条件行**，模型行左侧出现展开箭头（`aria-expanded`，点击 `stopPropagation` 不触发行点击的详情弹窗），展开区为该行下方 `colSpan=6` 的行集（列与主表对齐），每行 = 条件摘要 + 完整四价 + **该行自己的模拟费用**（场景 token 桶 × 该行价）。特殊行两类：**时段行**（dailySlots，有定义即展示、不看当前时刻——高峰/平峰一天内来回切换，隐藏没有信息量）与**上下文档位行**（contextTiers，按模拟场景的输入侧总量 `inputTokens + cacheReadTokens` 视作上下文长度，取满足 threshold 的最大档，命中才展示）。特殊行的来源跟随生效世界：命中时间规则时取该规则内部挂的 slots/tiers（此时根上的 slots/tiers 整体不出现——它们属于 base 世界，如 deepseek-v4-pro 在「第一次长期降价」期内没有高峰时段），未命中规则时取模型根上的。主行之外无任何特殊行则无箭头（命中规则的模型与普通模型外观一致）。真实 feed 形状：152 模型中 12 个带 timeRules、15 个文档位挂根上、2 个时段挂根上——三种展开形态都有真实样本。

**保持不变**：whole stats 响应不做瘦身（`pricing` 全表继续随用量响应）；单模型行内「定价」小按钮与未定价警告照旧。

## Alternatives considered

- **纯前端总览（复用 stats 响应里的 `pricing`，零后端）**——改动最小，但 merged flat 表已丢失别名关系（同名模型重复成行、无法区分主别名），且定价数据寄居用量响应、语义与筛选解耦的诉求相悖。输了：路由成本很低，换来独立语义与正确形状。
- **独立侧栏 section（`settings.section` 再注册一项）**——信息架构最清晰，但侧栏 +1 导航项、改动最大，且维护者明确要"做在设置 Token 用量页里"。输了：入口形态违背需求。
- **入口放页面标题行 / byModel 标题行**——标题行离工具区远；byModel 区域读作"受筛选约束的用量内容"，全量总览放那里语义自相矛盾（维护者的核心论证）。输了：筛选行行尾的"工具行"语义最贴。
- **入口做成标准边框按钮 / 灰字幽灵按钮**——边框按钮与三个选择器同族，行尾读作"第四个筛选控件"；灰字幽灵存在感过低，易被当静态文字。输了：蓝字链接在本项目已有"打开另一视图"的语义先例。
- **纯预设案例按钮（无输入框）**——一键选定经典档位，但数字不可微调，非经典用量只能心算换算。输了：四个 token 输入框补足任意值，案例按钮承担一键填充。
- **输入框裸 token 数（无单位切换）**——输入即精确值，但 98000000 这类数难读难输、易多敲一个零。输了：K/M/B 段选 + 案例按数量级精简回填，数字始终两三位。
- **桶区保留 4 个独立桶（各自边框）**——两行块（label-on-top）整组两行控件高、4 重 chrome；压窄到 `min-width: 130px` 的单行桶虽不 wrap（4 × 130 + 3 × 6 = 538px），但每桶 130px 内 label ≈ 28px、KMB ≈ 48px、gap ≈ 8px，只剩 ~46px 给数字——输入不了几位。输了：单行胶囊整组一条视觉线、单 chrome，`min-width: 0` 让压缩量由数字输入吸收。
- **桶区段内两行摆（label 段头小字、input/KMB 下排）**——label 与值视线分离、纵向多 ~14px。输了：单行段 12 件控件同处一条线。
- **桶区隐藏 spinner、自绘一对 +/- 按钮**——增加状态机与样式，且需单独处理与原生键盘上下键/滚轮的兼容；K/M/B 已承担跨数量级换算，spinner 只承担数量级内微调，Chromium 单引擎目标下原生足够。输了：webkit 伪元素两条规则即达。
- **模拟费用列两态排序（降/升来回切）**——少一次点击，但一旦点过就回不到默认家族序，浏览基准丢失。输了：三态循环多一次点击换回默认态，常见表格交互。
- **详情行内展开**——不打断浏览，但 166 行长表内嵌套价格表 + sticky 表头叠加，宽度与滚动关系复杂。输了：二级弹窗复用已验证的 PricingDialog 模式，视野集中，实现风险更低（维护者选定）。
- **家族分组折叠 + 已使用默认展开联动**（分组头折叠行、搜索激活 > 手动收展 > 已使用联动的三级优先级）——同族信息以分组头显式分段，默认视图聚焦当前在用模型；但折叠把行藏进组内，找模型要么先认家族、要么依赖搜索，三级优先级的实现、测试与心智成本都高，且默认 1d 窗口下大部分家族收起、多数模型不可见。输了：家族信息的价值在「同族相邻」，纯排序即可获得；平铺表所有行直接可见，Ctrl+F/滚动即达（维护者拍板平铺排序）。
- **分组但全部展开（无折叠、无联动）**——保留家族视觉分段又不藏行，但分组头 + colSpan 结构只为分隔存在，与搜索的交互语义仍要定义（组隐藏与否），信息密度低于行本身。输了：分隔行在 166 行里是噪音；纯排序已让同族相邻。
- **前端映射表推断家族**——按 modelId/别名关键词 + 首段前缀兜底推断家族，前端重复发明一份只会随上游漂移而失真，且实测上游 feed 每模型行自带 `family` 字段（16 家族全量覆盖）。输了：上游已有权威分类，零推断直出。
- **手工覆盖徽标 / 手工条目呈现**——总览若 ∪ 手工 `pricing.json` 条目并区分来源，需为每行携带来源标记；本地覆盖机制已废弃（见 [DR 2026-09-05](2026-09-05-abolish-manual-pricing-json.md)），总览只处理云端计价。输了：机制退场，呈现问题随之消失。
- **总览固定人民币**——与页面当前货币展示不一致。输了：跟随 `currencyViewOf` 几乎零成本，一致性更好（维护者选定跟随）。
- **顺带给 whole stats 响应瘦身**——69KB 全表随每次统计请求确属冗余，但本提案目标是定价表浏览；瘦身改变用量响应契约，属独立优化另行决策。输了：非本提案目标，保持现状风险最低。

## Consequences

- 换来：筛选行行尾「定价表」入口 → 总览弹窗列出云端镜像全部模型，平铺表按（feed `family` 字母序、家族内 modelId 字母序、缺失落 `other`）排序、所有行直接可见；搜索命中 modelId/别名/家族名并保序，当前筛选用过的模型行带「已用」徽标；行点开二级价格表弹窗，Esc/背板只关最上层。数据通道是本机路由读本地镜像（公网同步只发生在启动与区域切换时，弹窗永不直接依赖公网；云端 feed 挂掉时启动同步沿用旧镜像，弹窗照常有数据）。测试：路由/排序搜索纯函数/弹窗组件（vitest + testing-library）全绿，`node docs/decisions/check.mjs` 通过。
- 代价：
  - **全表 DOM 量**：166 行 × 6 列平铺直出，滚动壳内可控；上游 feed 若增长到数百模型，先靠搜索过滤与懒渲染缓解，虚拟化留到真需要时再做。
  - **案例清单是硬编码常量**：新案例需改代码发版（维护者按需追加，非用户可配）；按钮文案只显「案例N」，画像靠悬停 title；输入框不做持久化，每次打开预填第一个案例。
  - **桶区胶囊的最小呈现宽**：padding + 4 段 label/KMB 的自然宽度合计约 280px，低于此数字输入被压扁、unit 按钮间距吃紧；input 常驻轮廓在四段间是 4 条重复描边，与胶囊"单 chrome"意图有张力（可编辑区可见性优先）。
  - **spinner 常驻是 webkit 私有实现**：`::-webkit-*` 伪元素 Firefox 等非 webkit 引擎忽略，那里退回 UA 默认（hover 才显示）；dsh-web 目标浏览器为 Chromium，接受该偏差。
  - **生效价随真实日期漂移**：主行/排序口径取决于打开日的规则命中，规则边界日的前后费用与排序会变（语义如此，非缺陷）；jsdom 测试用远期/过期窗口固定命中状态。
  - **双通道全表冗余**：stats 响应与本路由各带一份全表（69KB 级），本次接受；stats 瘦身另行决策。
  - **top layer 层叠属浏览器视觉行为**，jsdom 无法模拟——层叠、焦点落位、连按两次 Esc 依次关两层降级为浏览器人工验证项；事件逻辑（close 只关最上层、target 守卫防误伤总览）由 jsdom 单测覆盖。
  - **`PricingDialog` 搬出 `TokenUsageSection.tsx`**：价格表样式与 byModel 表样式在两个 CSS module 各存一份同名类（CSS Modules 哈希隔离、内容一致），接受少量复制换取叶子模块边界。

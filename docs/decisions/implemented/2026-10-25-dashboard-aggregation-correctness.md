# DR: 看板性能样本与项目汇总的完整性边界

Status: implemented

## Problem

看板 review 发现两处统计偏差：平均耗时的分子只有有效计时请求，分母却包含无计时请求；项目列表在服务端按费用裁剪前 1000 个会话之后才在浏览器聚合，导致项目用量、排名甚至项目本身丢失。另外，固定双列卡片在主列变窄时不足以容纳固定宽度的数字列。

## Decision

> [!NOTE]
> 本决策中的设置区指标重排与共享列表密度已于 2026-10-25 由 [DR: 设置统计区保持两行指标与独立紧凑明细](./2026-10-25-settings-compact-dashboard.md) 取代；page 响应式与数据完整性约定继续生效。

- 部分取代 [公共看板与四卡片设计](./2026-10-24-usage-dashboard-isomorphic-board.md) 中性能耗时分母、项目客户端聚合和始终双列布局的约定，其余模型排序、目录尾段合并和会话子树折叠语义保持不变。
- 无计时请求不参与性能评价。`UsageTotals.perfLatencyCount` 只在成功请求具有有效 `latencyMs` 时增加；耗时均值使用该计数，速度和首字均值继续只取生成时长至少 500ms 且有输出的有效流式样本。性能行的次数为 `ModelPerf.timedRequests`，不再使用包含无计时请求的总请求数。用量和计费仍统计全部请求。
- rollup 聚合格式升至 `ROLLUP_AGGREGATE_FORMAT = 3`，首次读取旧格式从原始日文件重建有效计时计数；不猜测旧耗时总和的样本数。历史不可恢复时沿用既有保留用量和隐藏不可靠费用的兜底。
- 项目聚合移至共享纯模块 `src/project-rows.ts`，服务端先生成完整的根会话子树折叠行，再由完整集合生成 `projectRows`，最后只对 `sessionRows` 按费用裁剪前 1000 行。日期和模型过滤在聚合之前生效；子会话归属根会话目录，运行开销不归属项目。浏览器优先读取权威 `projectRows`；仅在旧宿主缺少该字段时保留原客户端折叠作为兼容回退。
- 布局跟随统计区实际容器宽度，而不是浏览器视口：小于 960px 的主列切为单列卡片；行列表小于等于 440px 时身份与数字分行、隐藏装饰性进度条，性能数字允许换行；page 指标窄于 1180px 时九轨降为五轨（历史四位费用仍能放下）、小于等于 600px 时改两列，小于等于 480px 时卡头和过滤条允许换行。设置指标固定四列两行；宽屏主列保留双列与原行式密度。
- 未定价模型的 Ctrl+点击过滤限制按用户确认保留，不在本次调整范围内。

## Alternatives considered

- **继续用全部请求数作耗时分母** —— 缺失计时不等于零耗时，会系统性压低历史数据和辅助调用混合模型的耗时，不能作为性能评价。
- **浏览器汇总前 1000 个会话，或直接扩大该上限** —— 前者无法生成完整项目统计，后者只是推迟同一个错误；项目聚合必须发生在会话展示裁剪之前。
- **仅按视口宽度切单列** —— 侧边栏和分栏会占用主列空间，同样视口可能容纳不同内容宽度，因此查询实际容器宽度。采用最近容器查询，不跨 CSS Module 共享容器名称，避免构建器对名称各自加作用域后查询失配。

## Consequences

- 代价：增加一项可回填的聚合计数和完整项目维度，首次旧 rollup 读取需要重建；旧宿主回退的项目统计仍受旧会话列表上限约束。
- 换来：缺失计时不再污染性能均值与样本次数，项目总量不受会话展示上限影响，窄主列无需横向滚动读取固定列。

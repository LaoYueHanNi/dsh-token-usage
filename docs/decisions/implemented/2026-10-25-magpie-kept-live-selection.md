# DR: Magpie 缓存读取与实时模型选择

Status: implemented

## Problem

[Magpie 适配器](2026-10-25-magpie-quota-adapter.md) 虽能按模型前缀筛选卡片，但浏览器只传供应商，后端读取最近一次请求的模型，导致首次请求前及同网关切换模型后筛选失效。另外，普通配额端点会触发供应商查询；输入栏的轮询与打开操作不应该驱动上游刷新。多账号报告也可能超出弹窗上方的可用高度。

## Decision

- 模型目录订阅同时读取 provider 和 model，二者任一变化均重新查询。HTTP 路由传递 `session`、`provider`、`model`；服务优先使用与 provider hint 配对的 model hint，不带 provider 的 model hint 不覆盖请求记录。旧调用方没有模型提示时，仍回退同供应商的请求记录。缓存与并发合并继续按 provider + model 隔离。
- 明确供应商前缀的模型只展示对应供应商；`auto/`、`group/`、裸模型名及无法匹配的前缀展示全量 Magpie 配额。公开模型 API 不暴露完整路由组成员，会话 route 仅反映一次请求的落点，因此不按名称或全局最近使用记录猜测组成员，也不依赖本机配置或 GUI 内部接口。
- Magpie 配额查询始终调用 `GET /v1/magpie/quotas?kept=1`。依据同级 Magpie 源码 `internal/gateway/gateway.go` 的 quotas handler，该分支只调用 `KeptQuotaReport`，不调用实时 `QuotaReport`。轮询、打开及重试没有实时兜底；空缓存或失败报告如实显示读取错误，用户在 Magpie 刷新读数。
- 弹窗选择按钮上下可用空间较大的一侧，按视口与裁切祖先的交集限制最大高度并保留边距，内容超长时内部滚动；窗口 resize 与祖先滚动重新测量，保留原有横向定位与宽度档位。宿主滚动区从顶栏下方开始，仅约束视口还不足以防止标题被其裁切。

## Alternatives considered

- **继续从最近一次请求推断模型** —— 尚未发请求时没有记录；同一网关内切换模型后记录也已过时，不能代表模型选择器的实时意图。
- **优先缓存、空缓存再实时读取** —— 会让首次打开或空缓存状态悄悄触发供应商查询，违背只消费网关缓存的边界；因此不采用旧记录中的实时读取选择。
- **只限制为视口总高度** —— 按钮不总在屏幕底部，视口总高度不是按钮上方可用高度，仍可能裁切；需实际测量并允许向下展开。

## Consequences

- 代价：数据新鲜度由 Magpie 的刷新机制决定，插件的读取时间不是上游刷新时间；空缓存时无法凭插件生成配额。同供应商的模型切换增加缓存读取，但不增加供应商请求。
- 换来：无需付费请求即可正确筛选模型相关卡片；高频 UI 操作不触发实时供应商查询；长报告在较矮窗口仍可完整滚动读取。

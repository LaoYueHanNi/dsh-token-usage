# DR: 将可证明归属的辅助请求纳入会话用量

Status: implemented

## Problem

实时请求池原本只观察 agent-loop 与压缩调用，标题生成和自动审查等辅助调用全部被视为全局运行开销。这个边界对旧宿主是必要的：Auto review 的 `llm/stream` 参数没有 `sessionId`，不能靠并发时序猜测它属于哪个会话。新版本的标题执行器明确把 `request.session.id` 写入 `GenerateOptions.sessionId`，因此标题请求已经有宿主提供的归属证据，却仍然从当前会话的请求池、趋势和按会话统计中缺席。

## Decision

- 继续把所有辅助调用记录为 `kind: 'aux'`，并保留 `auxKind` 分类。只有 `sessionId` 由宿主直接提供且请求类型可识别时才写入记录；当前标题生成请求归属 `session-title`，无 `sessionId` 的 Auto review、翻译和未知旁路请求仍使用空会话 id，保持全局运行开销口径。
- 实时观察器对带会话 id 的标题请求（以及未来带会话 id 的 Auto review）创建 `aux` 请求行。辅助行显示在对应会话或“含子会话”范围内，模型右侧贴短标签“标题”/“审查”等；它们的缓存评估固定为 `auxiliary` 排除，不显示“缓存过低”标签。失败、取消和无归属旁路调用沿既有规则处理。
- 辅助记录落盘后，运行观察器用同一会话、类型、路由和启动时间窗口把它链接到 `aux:<kind>:<time>:<seq>` 持久 id，避免实时行与日志行重复。持久化行保留 `kind`/`auxKind`，并参与该会话的 `total`、趋势、按模型和 `bySession`；未归属辅助行仍只参与全局维度与 `auxRows`。
- 实时请求表的指标顺序固定为“缓存命中、输入、输出、缓存读、缓存写、首字、耗时、速度、费用”；当展示池内没有任何请求报告缓存写桶时，整列（包括最新请求页脚项）隐藏。表格在窄容器中保持局部横向滚动，不隐藏仍有数据的指标。
- 请求池同时携带定价上下文解析后的 canonical `modelId`，模型名称展示该 ID；原始路由名仅保留在悬浮提示中，避免最新请求面板与历史列表的模型口径不一致。

## Alternatives considered

- **按当前活跃会话或最近一次请求猜测 Auto review 归属** —— 放弃：多个会话可并发，旁路参数没有稳定关联键，猜错会把费用和缓存数据污染到错误会话。
- **把所有辅助请求复制到每个会话** —— 放弃：总额与会话加总失去守恒，含子会话范围会重复计算。
- **只在落盘后显示标题请求** —— 放弃：标题生成可能持续数秒，用户需要在实时请求池看到它的生命周期；观察器与记录器通过持久 id 链接，避免双行。
- **把缓存读写放在最新请求的六个主指标中** —— 放弃：主指标顺序已稳定，缓存桶属于补充维度；表格列能在宽度足够时直接横向比较，面板页脚已有详细值。

## Consequences

- 代价：请求观察器增加辅助类型和一条跨监听器关联路径；启动时间窗口关联依赖两个监听器在同一进程内近邻执行，无法为无 session id 的调用制造归属；旧日志中的标题辅助行仍无法回补。
- 换来：标题生成等已证实归属的运行开销与会话的 token、费用、趋势和请求池口径一致；辅助请求不会触发缓存过低误报；实时表同时呈现缓存命中率与读写桶，且保留 20 行池和窄屏滚动行为。

# DR: 设置页新增完整定价表总览（独立路由 + 家族分组弹窗）

Status: proposed

## Problem

云端定价表（实测镜像 166 个模型）在 UI 上不可浏览：现有「定价」弹窗只能看统计筛选范围内出现过的模型的价，其余模型完全不可见。定价表的形状信息（modelId 与别名的关系）在 `cloudToTable` 展平后也丢了。整表数据其实已随 whole stats 响应下发（`attachCosts` 把 merged `PricingTable` 塞进 `pricing` 字段），只是没有 UI 消费它。语义上还有一层错位：按模型表是受筛选约束的用量视图，定价总览不受筛选约束——它需要独立的入口与数据通道，而不是搭在用量响应上。

## Proposal

**后端：新增 `/token-usage/pricing` exact 路由**（`stats-route.ts` 同模式：same-origin 校验、`no-store`、405/403 分支）。返回**模型行**形状而非 flat `PricingTable`：`models: [{ modelId, aliases, rules: ModelRates }]`——云端 feed 经 `coerceCloudPricing` 保留 models 数组形状直出。总览只呈现云端镜像：本地 `pricing.json` 手工覆盖机制已列入废弃计划，本提案不读它、不呈现它（连带地无来源区分、无手工徽标）。不用 flat 表的原因：`cloudToTable` 把别名展开成独立键，总览里同一模型会重复成多行同价行；保留形状让前端每模型一行、别名作小字附注、搜索可命中别名。无元信息（version/updatedAt/来源/同步时间——拍板不要）。`pricing.ts` 补一个保留形状的 cloud feed 读取函数（`readPricingTable` 的合并语义不受影响）。

**前端：入口**。位置在筛选行（FilterBar）行尾、模型菜单之后：行内三个控件是"选择器"（决定下方数据看什么），行尾入口是"动作"（打开与筛选无关的视图），不进筛选语法。形态是**蓝色文字标签**：`--dsw-alias-link-primary`（fallback `label-primary`）、无边框无底、28px 点击区（padding 4px 8px + 13px/20px）、hover 显 `interactive-bg-hover` 圆角灰底——链接 token 沿用 UsageView 子代理"下钻链接"的先例（`UsageView.module.css` `.childLink`），hover 灰底沿用 `dialogClose` 手法。文案用新 locale key（中文「定价表」/ 英文 "Pricing"），不复用单模型的 `pricing.viewShort`「定价」。

**前端：总览弹窗**。native `<dialog>`（PricingDialog 模式：showModal、Esc/背板关闭、焦点困住、top layer），宽度放宽到 `min(720px, calc(100vw - 48px))`。按需 fetch `/token-usage/pricing`（不带任何 query 参数——与筛选解耦，筛选变化不影响已打开的总览）。结构：搜索框（sticky 在弹窗顶部）+ 按家族分组的模型长表（列头沿用 `.tableWrap` 的 sticky `th` 模式）；每行 = 模型名（别名小字，截断为前 2 个 + `+N`）+ 基础定价 4 列（入/出/缓/写 ¥/M），货币跟随页面视图（`currencyViewOf`，USD 模式按汇率换算并在表下标注）。

**家族折叠与已使用联动**。分组头是可点击的折叠行（`groupRow` 分隔行模式：家族名 + 模型数 + 展开指示），点击切换该组收展。默认展开状态**联动页面数据**：弹窗打开瞬间从页面 stats 响应取「已使用模型」快照（当前筛选 `byModel` 的模型集合；`showModal` 期间 backdrop 盖住筛选行，筛选不可能变化，快照整窗稳定）——含已使用模型的家族默认展开，其余收起。优先级：**搜索激活 > 手动操作 > 默认联动**——搜索非空时含命中行的家族一律展开（搜索结果永不隐藏，未使用家族也能搜到看清）；已使用联动只在空搜索时决定默认状态；手动展开/收起在弹窗会话内保留，清空搜索后恢复。已使用模型行加 10px「已用」小徽标（风格同 `unpricedTag`），让联动结果可见。点击模型行 → **二级弹窗**展示该模型完整价格表（复用现有 PricingDialog/`ModelPriceTable`，native showModal 天然层叠：总览在下、详情在上），关闭回到总览。

**家族分组（上游字段直出，零推断）**。云端 feed 的每个模型行自带 `family` 字段（上游 model-price-table 规定；实测 version 76 镜像 166 模型全量携带、16 个家族值——gpt / google / spacex-ai / claude / qwen / mistral / glm / minimax / deepseek / kimi / doubao / mimo / step / tencent / meta / other），总览按该字段分组、家族名原样展示，前端**零映射表、零推断**。实现细节：`coerceCloudPricing` 目前只挑 rates/modelId/aliases/rules、会把 family 丢掉——需在 coerce 链透传（`CloudPricingModel` 加 `family?: string`，非字符串丢弃），总览路由的模型行形状随之带上 `family`；字段缺失的行落 `other` 组兜底（上游已自带该值，语义一致）。分组按家族字母序，组内按 modelId 字母序；搜索过滤行但保留分组结构。

**保持不变**：whole stats 响应不做瘦身（`pricing` 全表继续随用量响应，本次不动）；单模型行内「定价」小按钮与未定价警告照旧。

## Alternatives considered

- **纯前端总览（复用 stats 响应里的 `pricing`，零后端）**——改动最小，但 merged flat 表已丢失别名关系（同名模型重复成行、无法区分主别名），且定价数据寄居用量响应、语义与筛选解耦的诉求相悖。输了：路由成本很低，换来独立语义与正确形状。
- **独立侧栏 section（`settings.section` 再注册一项）**——信息架构最清晰，但侧栏 +1 导航项、改动最大，且维护者明确要"做在设置 Token 用量页里"。输了：入口形态违背需求。
- **入口放页面标题行 / byModel 标题行**——标题行离工具区远；byModel 区域读作"受筛选约束的用量内容"，全量总览放那里语义自相矛盾（维护者的核心论证）。输了：筛选行行尾的"工具行"语义最贴。
- **入口做成标准边框按钮 / 灰字幽灵按钮**——边框按钮与三个选择器同族，行尾读作"第四个筛选控件"；灰字幽灵存在感过低，易被当静态文字。输了：蓝字链接在本项目已有"打开另一视图"的语义先例。
- **详情行内展开**——不打断浏览，但 166 行长表内嵌套价格表 + sticky 表头叠加，宽度与滚动关系复杂。输了：二级弹窗复用已验证的 PricingDialog 模式，视野集中，实现风险更低（维护者选定）。
- **搜索激活时仍按「已使用 ∩ 命中」决定展开**——严格继承联动语义，但搜索未使用家族时命中行全在收起组里、结果被藏起来。输了：搜索的第一义务是让结果可见；联动只该管默认态，不该收窄搜索。
- **默认全部展开（无联动、无折叠）**——实现最简，但 166 行全铺与「聚焦当前在用」的使用直觉相悖，且折叠 + 联动的成本很低（一个 Set + 三级优先级）。输了：维护者要折叠与联动，全部展开只留作清空搜索后的回退基线之一。
- **前端映射表推断家族**——曾按 modelId/别名关键词 + 首段前缀兜底推断了 14 家族；后确认上游 feed 每模型行自带 `family` 字段（16 家族全量覆盖）。输了：上游已有权威分类，前端重复发明一份只会随上游漂移而失真。
- **手工覆盖徽标 / 手工条目呈现**——总览原可 ∪ 手工 `pricing.json` 条目并区分来源；维护者已决定废弃本地覆盖机制，总览只处理云端计价，来源区分无从谈起。输了：机制本身退场，呈现问题随之消失。
- **总览固定人民币**——与页面当前货币展示不一致。输了：跟随 `currencyViewOf` 几乎零成本，一致性更好（维护者选定跟随）。
- **顺带给 whole stats 响应瘦身**——69KB 全表随每次统计请求确属冗余，但本提案目标是定价表浏览；瘦身改变用量响应契约，属独立优化另行决策。输了：非本提案目标，保持现状风险最低。

## Acceptance criteria

- 筛选行行尾出现「定价表」蓝字入口；点击打开总览弹窗，数据来自 `/token-usage/pricing` 且请求不带筛选参数；改变筛选不影响已打开的总览内容。
- 总览列出云端镜像全部模型，按 feed 的 `family` 字段分组（家族字母序、组内 modelId 字母序，缺失落 `other`）；每行显示模型名、别名小字、基础价 4 列；货币跟随页面区域设置（CNY 原值 / USD 换算 + 汇率标注）。
- 搜索框命中 modelId、别名与家族名（大小写不敏感子串），过滤保留家族分组结构；空搜索显示全部。
- 折叠联动：弹窗打开时含「已使用」模型的家族（当前筛选 `byModel` 快照）默认展开、其余收起，已使用行带「已用」徽标；搜索非空时含命中行的家族全部展开，未使用家族的搜索结果直接可见；手动收展在弹窗会话内保留，清空搜索后恢复默认联动。
- 别名小字超过 2 个截断为前 2 个 + `+N`；行高不因别名数量变化。
- 点击模型行打开二级价格表弹窗（计费条件 × 入/出/缓/写），Esc/背板只关最上层，关闭后回到总览。jsdom 单测（事件逻辑层）：两弹窗同开时派发 Esc，断言仅详情弹窗关闭、总览状态与滚动不受影响。
- 弹窗数据通道是本机路由读本地镜像（公网同步只发生在启动与区域切换时，弹窗永不直接依赖公网；云端 feed 挂掉时启动同步沿用旧镜像，弹窗照常有数据）。获取失败或镜像为空（首次启动同步即失败）统一提示「模型定价获取失败」+ 重试（重新 fetch 本机路由），不阻塞设置页其余部分。
- 新增路由 / 折叠联动 / 弹窗组件测试遵循现有测试模式（vitest + testing-library）；`node docs/decisions/check.mjs` 通过。

## Risks

- **全表 DOM 量**：166 行 × 5 列 + 分组头，滚动壳内可控；上游 feed 若增长到数百模型，先靠搜索过滤与懒渲染缓解，虚拟化留到真需要时再做（现在不做）。
- **二级弹窗层叠语义**：native showModal 后开者在 top layer 之上，理论层叠成立；top layer 是浏览器视觉行为、jsdom 无法模拟——层叠与 backdrop 降级为实施时的浏览器人工验证项（详情叠在总览上、焦点落位、连按两次 Esc 依次关两层），事件逻辑（Esc 只关最上层、`close` 互不误伤）由 jsdom 单测覆盖。
- **已使用联动受默认窗口影响**：页面默认 1d 窗口下已使用模型可能只有两三个，弹窗打开只有少数家族展开——这是「聚焦当前在用」的设计意图而非缺陷；切日期筛选后重新打开弹窗即可看到更宽的联动面。
- **上游 family 语义漂移**：分组完全跟随 feed——新增/改名家族自动生效，前端零映射逻辑、无维护成本（原映射表方案的维护风险随之消除）；家族名是上游的权威命名（含 `spacex-ai` 这类趣味归组），总览原样展示不翻译、不质疑。
- **双通道全表冗余**：stats 响应与本路由各带一份全表（69KB 级），本次接受；stats 瘦身另行决策。
- **货币换算源**：与用量页同用 feed 汇率（缺省 7），无新增风险源。

# DR: rollup 增加会话维度，设置页提供跨会话统计表

Status: proposed

## Problem

设置页的统计目前只有日期和模型两个筛选维度，回答不了"这个月哪个会话花钱最多""哪些会话在烧 token"这类跨会话问题。数据层每条 `UsageRecord` 都带 `sessionId`，但 rollup（`src/rollup.ts`）的行是 (day, model, rate identity) 单元，刻意没有会话维度；会话级查询只能走 `filterRecordsBySessions` 折叠原始记录（`src/stats.ts` `filterRecordsBySessions` 上方注释明言 rollup 无会话维度、整页读取不可复用）。结果：设置页无法按会话筛选或排行，会话级聚合随历史记录数线性增长，且没有聚合层可复用。

## Proposal

**数据层**：给 `RollupFile` 与 `TokenSummary` 新增 `bySession: UsageSessionRow[]` 维度，行粒度为 **(sessionId, day, model, rate identity)** 单元，另带 `lastTime`（该单元内最新记录时间，折叠取 max）。四个粒度成分各有必要：

- `day`——会话常跨天，日期筛选下会话行的数字必须只含窗口内部分；
- `model`——模型筛选同理，且与 `filterSummary` 从 rateRows 重聚合的既有模式一致；
- `rate identity`——费用聚合必须从带规则身份的单元出发（`attachCosts` 现状），价格表更新后历史免费重定价；
- `lastTime`——会话表按"最近活跃"排序展示。

失效记录（`model === ''` 的 failure 行）按 sessionId 正常折叠进会话单元（rate 取 UNPRICED）——rateRows 本就不在行粒度上排除 model=''（`filterSummary` 只在派生 byModel 时排除），会话维度保持同一语义，保证请求数对账一致。派生路径随之逐一定点扩展：`summarizeRecords` 折出 bySession；`mergeSummaries` 按 (sessionId, day, model, rate) 键折叠它（lastTime 取 max）；`filterSummary` 从它重聚合（与 rateRows 同模式）；`attachCosts` 从同一单元计费——费用对账因此免费成立。

设置页的按模型表升级为一个**可切换的明细表区块**：表头处一个切换器（按模型 / 按会话），默认按模型，保持现有外观与行为不变；切到按会话时同位置渲染会话表，列：会话（标题为主标识，所属项目目录尾段为辅标识）、请求数、总 token、费用、失败、最近活跃；默认按费用降序，截断展示前 N。两份行集（`byModel` / `bySession`）来自同一次 summary 响应，切换是纯前端呈现状态（会话内有效，不持久化，与 UsageView 的 scope 开关同一取舍），不多发请求。

会话表自带**作用域切换**（沿用 UsageView 的 Session / 含子代理开关模式）：**折叠（默认）**——行 = 顶层会话，行数字 = 该会话及其全部后代在当前筛选下的用量之和，徽标标注子代理数；**平铺**——行 = 全部会话（含子代理，徽标标注），各行只计自身。折叠规则：根 = 无 `parentSession` 或父会话不在索引的会话（孤儿按顶层处理，保证求和不变），嵌套子代理折叠到最顶层根；折叠在筛选后的 `bySession` 单元上、响应时计算，磁盘不存折叠结果。折叠改变行排名（父行按子树总费用排序），top-N 截断必须发生在折叠之后，故作用域是查询参数、切换时重发请求——与按模型/按会话的纯前端切换不同。子代理的记录本就计入整页汇总卡与按模型表（现状语义，不变），会话表两种作用域都覆盖子会话，列和才能与汇总卡对账。

会话表支持**按工作区目录分组**（仿照宿主会话侧栏的分组观感）：目录头 + 组内行，无 cwd 的会话归入"未指定目录"组，分组状态下目录辅助列并入组头。**默认分组**，可切换为不分组列表（纯前端呈现，行已由服务端并入 cwd，切换不发请求；会话内有效，不持久化）。不读取也不写宿主设置：宿主侧栏的显示偏好在本插件可见的依赖面内没有已发布读取口（侧栏属宿主未随插件安装的 UI 包），为取一个默认值而依赖宿主内部形态不值，插件自持开关、两组呈现互不影响宿主。会话表行本身默认无点击行为（与按模型表一致）；可选增强：点击会话行把整页筛选切到该会话（汇总卡、趋势图、明细表随之只显示该会话，再次操作可退回整页视图）——复用现有 `sessionIds` 查询参数与 session-scoped payload 路径，服务端能力已存在，纯前端接线。

**兼容**：旧 rollup 缺 `bySession` 字段 → `isRollupFile` 校验失败 → 视为缺失、从日文件一次性重建（现有鲁棒路径，record-cache 缓解 IO）。不做可选字段惰性迁移——已吸收的冻结日文件不会重读，无法补出会话维度，硬性失效重建是唯一诚实路径。

**会话元数据索引（本期需求）**：sessionId 对用户几乎不可读，会话表以标题为主标识、所属项目目录为辅标识。索引为数据目录下的 `sessions.json`：sessionId → `{ title?, cwd?, origin?, parentSession? }`（非默认字段缺失即省略）：

- **标题**来自日志背书的 latest-wins `session/title` 事件（宿主 `SessionEventMap` 声明）。折叠由插件本地实现：取最后一个 title 事件的文本，宽容归一化（非字符串标题跳过），不为此引入 `@deepseek-ai/dsh-session-title` 新依赖——本插件用不到其 snapshot 的 seq/来源字段，而该项目连 type-only import 的官方包都声明进依赖，引入即多一个与宿主版本线独立演进的包；
- **目录与子代理亲缘**来自 `SessionHeader` 的 `cwd?` / `origin?` / `parentSession?`（宿主创建会话时已持久化），所需的 `session.header` 与 `SessionInspection.meta` 来自已在依赖清单的 `dsh-session` / `dsh-session-persistence`，零新增依赖；
- **live**：现有 `ctx.on('session/event')` 监听里捕获 `session/title` 事件，latest-wins 更新标题——用户改名（`rename` 落 `source: 'user'` 事件，只发生在 live 会话上）、自动生成、fallback 最终都是 append 同一事件，谁 seq 大谁生效，一条分支覆盖全部时机，无需单独的改名同步路径；header 元数据（cwd/亲缘）从回调入参 `session.header` 读取，按会话首次见到时 upsert 一次（header 不可变，无需逐事件重写）；
- **历史回填**：`syncHistory` 本就逐事件遍历每个会话日志，顺手折出标题、并从 `inspect()` 返回的 `SessionInspection.meta`（header）读取 cwd 与亲缘并入索引——已安装用户的老会话元数据随一次全量同步补齐。插件的 `SyncPersistence` duck 类型需同步扩展：`inspect` 的返回从 `{ events }` 增至 `{ meta, events }`（宿主本来就返回 header，只是现实现未取）；
- **韧性**：索引是从会话日志可完整重建的派生缓存，损坏即视为缺失，靠手动/自动全量同步重建，不做增量修补。写入沿用 `state.json` 的 temp+rename 原子写，并经单写队列串行化（与 UsageLog 的 append 队列同一模式，防并发 upsert 互相踩踏）；文件在数据目录内，随目录迁移整体移动，无需迁移逻辑；
- **服务**：元数据（标题/目录/亲缘）由服务端并入会话表行内——行是服务端折叠、排序、截断后的最终结果，行内自带标识最直接，也免去客户端二次拼装；会话页 Usage 标签页的 `chip` / `session` 分层 payload 不受影响。索引文件小，读取加 mtime 缓存（与定价表同一策略）；
- **回退**：无标题事件的会话（部分子代理、老数据）显示 sessionId 短形式 + 起止时间，不臆造标题；header 无 cwd 的会话省略目录标识，留空即可。

## Alternatives considered

- **不改格式，设置页每次从 `readCachedRecords` 现折叠会话表** —— 零格式变更、零迁移，且冻结记录本就常驻内存，10 万条记录折叠约几十毫秒，短期完全可用。但整页读取语义反转（现有注释明言 settings 页 whole-log read 不折叠 raw），每次筛选变更 O(records) 且随历史无上限增长；今日热文件本来就要现折叠，冻结部分却放着现成聚合层不用。输了：把已知会线性恶化的路径当成正式方案。
- **独立会话用量聚合文件（sessions.json 之类），与 rollup 平行惰性吸收** —— 指把 token 聚合搬出 rollup 的方案：需要多一套吸收/原子写/派生态失效逻辑（`invalidateDerivedState` 多删一个文件），换来的仅是 rollup 文件不变大。输了：两套机制维护成本大于一份变大的 JSON。（注意：本 DR 最终仍新建一个 `sessions.json`，但那存的是会话标题元数据——可从日志重建的缓存，不是用量聚合，性质不同，不与此冲突。）
- **rollup 只存 (sessionId → totals) 汇总** —— 行数最少，但跨天会话在日期筛选下数字错误（会话总量 ≠ 窗口内分量），模型筛选同样失真。输了：筛选正确性是硬需求，错误的聚合比没有聚合更糟。
- **rateRows 直接加 sessionId 进键** —— 信息等价于新维度，但会把无会话需求的既有读取路径（整页汇总、模型表）也背上会话基数，且破坏 rateRows 的语义稳定性。输了：加法式新增 `bySession` 让现有字段与路径零改动。
- **标题从客户端会话树 store 取（`useSessions` 的 displayTitle）** —— 只覆盖客户端 mirror 已加载的会话，且设置页上下文不保证有该 store 可用。输了：插件自持索引对任意历史会话都成立，且不依赖宿主 UI 内部形态。
- **标题在响应时按需 `persistence.inspect` 会话日志** —— 每次统计请求 N 次会话日志 IO，把成本放在最热的读路径上。输了：索引把成本移到写路径与一次性同步，读路径零额外 IO。
- **标题写进 UsageRecord** —— 标题随时间变化（latest-wins）且与单条请求无关，污染记录语义、逐行放大 JSONL 文件。输了：会话级属性进会话级索引。
- **会话表仅平铺（不做折叠）** —— 实现最省，但重度子代理用户的表被大量短会话行淹没，"哪个会话烧钱最多"只能人工归并。输了：UsageView 已用 scope 开关解决过同一问题，模式现成，折叠只是响应时的一次单元归并。
- **会话表仅折叠（子代理不可见）** —— 表面干净，但丢失子代理可见性与"平铺看单行"的能力。输了：在折叠默认之上加一个平铺切换的边际成本很小。
- **客户端折叠（服务端发平铺全量行 + 亲缘映射）** —— 切换作用域不发请求，但折叠改变行排名，正确的 top-N 截断要求把全部行发给客户端，传输量随会话数无界。输了：服务端折叠 + 作用域参数把传输量钉在前 N 行。
- **引入 `@deepseek-ai/dsh-session-title` 依赖做标题折叠** —— 官方 fold 保证语义跟随宿主演进，但本插件只需要 latest-wins 的标题文本，为此新增一个与宿主版本线独立演进的依赖（0.1.0-rc.x）不值；该项目连 type-only import 的官方包都声明依赖，引入即有安装与对齐成本。输了：几行本地宽容折叠已覆盖所需。
- **把插件的分组偏好写进宿主设置节（跟随并联动宿主）** —— 越权写其他节，且直接改变宿主侧栏行为。输了：分组是插件自己的呈现开关，两组呈现都不该碰宿主。
- **读取宿主侧栏"列表/分组"偏好作为默认值** —— 跟随最"像宿主"，但该偏好在本插件可见的依赖面内没有已发布读取口（侧栏属宿主未随插件安装的 UI 包），为此依赖宿主内部形态（或等待其暴露 API）不值。输了：默认分组已贴合宿主观感，成本为零且不引入任何耦合。

## Acceptance criteria

- 明细表区块默认展示按模型，外观与行为和现状一致；切换到按会话后，同一筛选下会话表各列之和与汇总卡/按模型表对账一致（同一 summary 派生保证）。
- 日期范围与模型筛选联动会话表：跨天会话在窗口内的行只计窗口内部分。模型筛选不豁免——会话行显示该会话落在筛选内的切片，零匹配会话从列表消失；筛选激活时表语义自然变为"该模型被哪些会话消耗"（模型×会话交叉分析），且各列之和保持与汇总卡对账。
- 折叠与平铺两种作用域下，会话表各列之和均与汇总卡一致（折叠保和、平铺全覆盖）；筛选先于折叠生效，折叠父行显示子树在筛选内的用量；折叠排名与 top-N 截断由服务端完成。
- 目录分组默认开启、可切换为不分组列表；分组只是呈现重组，组间行集与不分组时完全一致；插件不读也不写宿主设置。
- 有标题事件的会话在会话表显示标题：live 改名即时反映，历史会话经回填补齐；无标题会话回退 sessionId 短形式 + 起止时间。有 cwd 的会话显示所属项目目录尾段，子代理行带徽标；两者缺失时对应标识省略。
- 含历史数据的旧目录首次读取自动触发一次 rollup 重建，重建前后统计结果不变；rollup 损坏回退重建路径不回归。
- 若实现会话行点击筛选：点击会话行后整页统计只显示该会话（复用 `sessionIds` 路径），可退回整页视图。
- 新增测试遵循现有测试模式，并至少覆盖：折叠算法的求和不变（孤儿按顶层、嵌套到根、环防御性截断）、元数据索引 store（原子写、损坏重建、upsert 幂等）、旧 rollup 重建前后对账、路由作用域与筛选参数组合；`node docs/decisions/check.mjs` 通过。

## Risks

- **rollup 文件与内存聚合随会话数增长**：行数 ≈ 每天 (会话 × 模型 × rate) 组合数，常规使用每天数十行、年累计万级行，JSON 可控；重度子代理用户（每天上百短会话）会放大——接受，必要时后续对服务端传输加截断或对超旧会话归档。
- **旧格式一次性全量重建**：升级后首次统计读取变慢（读全部冻结日文件），record-cache 已把冻结文件常驻内存，属一次性成本；重建失败不阻塞读取（现有路径）。
- **老安装的元数据回填要一次全量遍历**：`autoSyncIfNeeded` 的 initialized 标记已存在，不会自动重跑。标记放在数据目录现有的 `state.json`（`src/sync-state.ts`）里加可选字段 `metaSyncedAt`——缺失即未补齐，沿用"缺失/畸形读作未完成、重跑幂等、原子写"的既有语义，不新建标记文件。补齐动作就是把标题折叠与 header 元数据捕获做进 `syncHistory` 后再跑一次：元数据与用量行在同一个会话日志里，元数据-only 遍历在 IO 上并不比全量同步便宜，而老安装这次遍历的用量行会被 requestId 去重全部跳过（零写入）。新安装的首次自动同步顺手写入两个字段；手动"重新扫描"因此自动获得元数据修复能力，无需单独路径。
- **无标题会话的可读性回退**：部分子代理会话与老数据没有 `session/title` 事件，显示 sessionId 短形式 + 起止时间；不调用 `fallbackSessionTitle` 臆造标题（那是宿主服务的职责，插件只认日志里真实落过的事件）。
- **折叠语义的边界情形**：宿主 header 持久化亲缘（`origin: 'subagent'` / `parentSession`），索引捕获后折叠成为可能；边界统一为——父会话不在索引的孤儿按顶层处理、嵌套子代理折叠到最顶层根、亲缘成环（理论上不可能，防御性截断按顶层算）。规则都朝"求和不变"收敛，错了也只是分组错、总量不会错。
- **磁盘格式变更**：rollup 与 wire 均为跨版本契约，实施须同步更新相关决策记录与 `check.mjs` 校验。

# DR: 提供商前缀兼容、上游别名正则与未定价模型手动关联

Status: proposed

## Problem

提案提出时，插件把云端镜像 `pricing.ccsa.json` 的 `modelId` / `aliases` 展开成精确匹配表。带 `provider/` 前缀的用量名无法命中短名称；上游 model-price-table v110 新增的 `aliasPatterns` 又被 `coerceCloudPricing` 丢弃，新增正则别名无法参与计费。相关名称不一致问题见 [GitHub issue #10](https://github.com/LaoYueHanNi/dsh-token-usage/issues/10)。

上游的 [模型识别协议](https://github.com/LaoYueHanNi/model-price-table/blob/c5c17dc/README_zh.md)（2026-10-10 核对的提交 `c5c17dc`）要求全表分阶段识别：精确 `modelId`、精确历史 `aliases`、完整正则；名称区分大小写，同阶段跨模型命中报歧义。`aliases` 已冻结，后续新别名只维护在 `aliasPatterns`。直接使用 `contains` 无法保持模型身份：当前表同时有 `glm-5.3-flash` 与价格不同的 `glm-5.3-flashx`，不能因为包含同一字符串就视为同价。

自动识别仍无法覆盖内部代号等完全异名。用户需要在未定价位置直接搜索、选择已有价目，并能看见、撤销这项关联；真正缺少价目的模型则需要快捷向上游提交请求。这条补救路径必须遵守 [废除手工 pricing.json 定价文件机制](../implemented/2026-09-05-abolish-manual-pricing-json.md)：本机只保存名称关联，不保存价格，不覆盖云端完整规则。

现有 [按模型表按定价别名折叠到 modelId](../implemented/2026-09-10-bymodel-folds-pricing-aliases.md) 只处理精确别名，且允许别名碰撞时先写者赢。新增识别必须贯通费用、折叠、筛选、会话视图与「已用」标记，不能只修一处查表。历史 `rollup` 还保存 `RateKey`，新增关联后仅套上目标单价会沿用旧的未定价或其他模型的规则身份，可能错误跳过时间规则、上下文档位和峰谷槽。

## Proposal

本记录保留整体设计与后续阶段，状态继续为 proposed。第一阶段自动识别已由 [统一模型自动识别与带定价指纹的历史重算](../implemented/2026-10-10-model-pricing-resolution.md) 落地；下文自动链与统计契约是后续关联工作的基础，关联文件、保存／撤销接口、局部搜索界面与上游 Issue 草稿入口尚未实施。第二阶段实施关联后端，第三阶段实施关联界面，各阶段独立验证并提交到 codex/feature-model-pricing-resolution，不合并 main、不推送、不打版本、不发布。

### 自动识别顺序与归一化边界

以记录上的原始名称 `rawName` 为输入，在同一份有效 feed 快照上执行以下三个阶段。每个阶段在全表范围查找；唯一命中才结束，零命中才继续，歧义立即停止自动识别并保持未定价，不得去下一阶段挑一个结果。

1. **精确匹配**：先对原始完整名称忽略大小写匹配全表 `modelId`；没有任何命中才对原始完整名称忽略大小写匹配历史 `aliases`。「精确」指完整名称相等，不要求大小写相同，不剥离前缀，不修剪空白。同名既是某模型的 ID 又是另一个模型的 alias 时，ID 阶段优先；两个模型声明同一 alias 时则报歧义。同一模型中仅大小写不同的 alias 视为同一个名字，重复命中只算该模型一次；仅大小写不同的 `modelId` 不代表不同模型，而是重复 ID，属于 feed 校验错误。
2. **归一化匹配**：仅当名称有 `/`、各路径段非空时，取最后一个 `/` 后的子串作为唯一候选 `normalizedName`，再执行「忽略大小写完整匹配 modelId → 忽略大小写完整匹配历史 aliases」。支持 `provider/model` 与多段命名空间；无 `/` 时大小写差异已在第一阶段处理，无需重复查找；前导 `/`、尾随 `/`、连续 `/` 不产生归一化候选。第一、二阶段统一用不依赖系统语言环境的 `String.prototype.toLowerCase()` 生成比较键；不修剪空白，不改变标点、版本或后缀，不删除 `flash` / `flashx` / `fast` / `pro` / `mini` / 身份中的 `max` 等部分。feed 键只做大小写比较，不去前缀，不使用子串或近似匹配。
3. **别名正则匹配**：精确与归一化均未命中时，在全表 `aliasPatterns` 上匹配原始名称及有效的去前缀候选（无 `/` 时不重复匹配）。消费端统一使用 `new RegExp(pattern, 'i')` 忽略大小写，仍要求匹配范围覆盖整个输入。两个候选的命中模型取并集；同一模型的多条正则、同一模型同时匹配两个候选均只算一次，命中不同模型则报歧义。保留正则源码及输入的原始拼写，不通过改写正则文本实现忽略大小写。

这是插件明确增加的 **provider 前缀与大小写兼容层**：上游自身不剥离前缀且名称区分大小写，而本插件按用户要求在三个阶段统一忽略大小写，在精确与正则之间增加去前缀阶段，并给正则提供去前缀候选。正则源字段仍遵循上游无 flags 的数据格式，消费端固定添加 `i` 是本插件明确的行为扩展；正则语法、完整匹配、模型身份保留及真实的跨模型歧义规则照常遵守。不把这层扩展描述成上游默认行为。原始完整名称命中优先于归一化，归一化命中也优先于原始名称的正则命中。

例如 feed 只有 `glm-5.3` 时，`GLM-5.3` 在第一阶段命中，`z-ai/glm-5.3` 与 `z-ai/GLM-5.3` 在第二阶段命中；`CLAUDE-OPUS-5-5-THINKING-HIGH` 也能命中对应小写别名正则。返回的规范 ID 保留 feed 中的实际拼写，原始用量记录和关联的展示名称也保留原始拼写；大小写不是区分模型或选择价格的依据。

三阶段均无命中、或某阶段歧义且未获人工解决，均没有可用定价。费用计算维持现有未定价占位行为，UI 显示「未定价」与 `—`，总费用说明不含这些模型；真实零单价模型是「已定价」，不能凭费用为零判断未定价。歧义额外显示原因和候选 ID，区别于「未找到模型」；feed 无法加载则显示定价表不可用，区别于正常表中的缺项。记录中的空模型名仍是未归属用量，不生成空白待关联行，也不允许保存空名称关联。

### 上游字段准入与正则校验

- `aliasPatterns` 仅位于模型根节点；缺省按 `[]`。显式提供时必须是唯一、非空字符串组成的数组。保留历史 `aliases`，旧 feed 无正则字段时仍可精确匹配。
- 在加载 feed 时校验并编译一次，使用上游文档允许的 ECMAScript 字面字符、转义标点、分组、分支和可选 `?`。要求首尾 `^` / `$`；上游字符串不带分隔符或 flags，消费端编译时固定使用 `i`，不使用有状态的 `g` / `y` 或改变锚点语义的 `m`。禁止未转义的通配符、无界量词、前后查找、反向引用和内联 flags；不能仅靠 `new RegExp()` 编译成功就认定合规。
- 执行时检查匹配起点为 0 且匹配长度等于整个候选长度；单纯 `.test()` 加 `$` 会接受部分末尾换行情形，不满足协议。忽略大小写不放宽完整匹配与模型身份要求，不移除后缀后再匹配。
- 类型错误、重复正则、非法或不支持的正则、忽略大小写后的重复模型 ID 均是 feed 校验错误，不静默丢弃字段、合并价目或挑选一行。同步必须先验证整份新 feed，再原子替换镜像；失败保留上一份有效镜像并报告同步错误。启动读取磁盘镜像也须校验；没有有效镜像时自动识别与手动目标选择均不可用，宿主和用量读取继续工作。
- 同阶段命中不同模型是识别错误，不按模型数组、正则数组或对象键顺序择一。已知 ID / alias 的跨模型正则覆盖应作为上游数据诊断，但精确命中优先规则仍生效；不能让后置正则推翻精确 ID。

### 手动关联的作用与生命周期

手动关联是自动识别失败后的显式补救，不插在三个自动阶段之间，也不提供已自动定价模型的本地改价入口。保存的是 **原始用量名 → 当前 feed 中的精确 modelId**。

- 来源按原始完整名称忽略大小写匹配，作用域为当前插件数据目录内的全部用量与会话。`provider-a/foo` 与 `provider-b/foo` 可各自关联；关联 `provider-a/foo` 同样适用于 `PROVIDER-A/FOO`，但不会连带影响 `foo` 或其他 provider。原始记录、路由配置与 feed 均不改写；管理界面保留用户选择时的原始拼写，并可查看受该关联影响的用量名。
- 目标必须是当前有效 feed 的唯一 `modelId`，不能是 alias、正则文本、另一条本地关联或新建价目。目标 ID 也按完整名称忽略大小写查找，保存和返回采用 feed 的实际拼写；仅大小写调整不使目标失效。禁止链式关联与自定义单价，完整继承目标的 `timeRules` / `contextTiers` / `dailySlots` 以及汇率显示规则。
- 允许给「无命中」或「歧义」的原始名选目标。保存时服务端重新验证来源仍无唯一自动结果、目标仍有效；页面打开后 feed 已变且来源已能自动识别时，拒绝保存并返回最新状态，不能以旧页面覆盖当前自动识别。
- 三阶段失败后，已有有效关联可提供人工指定的价格，状态必须标记「手动关联」。无关联、目标失效、关联存储损坏时仍无定价；不得偷偷按相近目标补价。
- 上游更新后若自动识别有唯一结果，自动结果优先，保留原关联为「已由自动识别接管，关联未生效」。若自动目标与保存的人工目标不同，明确显示两个目标及不一致提示，不静默删掉用户选择。自动识别再次失败且原目标仍有效时，保存的关联重新生效；停用关联的界面须保留撤销入口并说明这一行为。
- 上游删除 / 重命名目标时保留原条目，显示「关联目标已失效」，可重新选择或撤销；不把保存的目标当 alias 去追踪到另一个模型。同一 ID 保留但价格更新时使用最新规则，不保存价格快照；切换 feed / 区域后按当前 feed 重新判断目标，可能失效或被接管。
- 修改、撤销作用于这一原始名称的全部历史和后续用量。撤销删除关联条目后重新执行自动识别：可能恢复未定价，也可能由现有自动规则定价，不能承诺撤销必然变成零费用。

### 局部搜索、关联标记与上游请求

未定价警告中的每个模型提供「关联已有模型」和「向上游请求定价」；按模型表未定价行也能直接打开相同的关联面板。设置页和会话用量页共享交互与数据接口；用户留在当前页面、当前日期 / 模型 / 会话筛选，不必先打开整张定价总览再找模型。

关联面板显示原始名、失败原因，若歧义则列出候选；搜索框可用去前缀候选预填，但文本始终可编辑。候选来自本机已同步的完整 feed，不受用量筛选范围限制、不直接请求公网。复用 [定价表总览](../implemented/2026-09-05-pricing-table-overview.md) 的 modelId / 历史 aliases / family 搜索和家族排序：搜索允许忽略大小写、子串过滤，这仅用于找候选，**不参与自动计费**。若输入作为模型名称命中合法正则，也可把对应模型列为候选，但不将用户输入当成正则执行。

列表每个 feed 模型只列一行，显示明确的 `modelId` 与简要价目，能查看完整时间 / 档位 / 峰谷规则；搜索价格只作当前生效价预览，不能当成历史实际单价。点选后展示「原始名 → 目标 ID」及「应用于该名称全部历史和后续用量」，由保存动作提交；候选唯一也不自动保存。无结果时保持搜索框并提供上游入口。加载失败可原地重试，保存中防重复提交，保存失败保留选择、显示错误而不假装生效。关闭取消不写入任何关联；键盘操作、Esc / 背板与焦点恢复沿用现有弹窗约定，详情关闭不误关外层。

按模型表继续按定价 `modelId` 折叠，费用与请求数不重复。一个折叠行可能同时包含直接、归一化、正则和手动来源；只要有正在生效的手动关联，就显示「含手动关联」标记，并可展开 **每个原始名 → 目标 ID**、状态、修改 / 撤销动作，不能只显示折叠后的目标名而丢失关联来源。仍未定价的名称按原始完整名称忽略大小写分组，展示其中一个原始拼写并可查看全部大小写变体；不同完整名称保持独立，不因为去前缀候选相同而合并。筛选匹配采用相同口径，不因查询参数大小写变化漏掉用量。

关联管理列表可从未定价警告或按模型表的关联入口在当前页面打开，列出当前目录保存的全部关联；不受当前用量筛选限制。因此没有落在当前日期内的关联、失效关联、被自动接管的关联也能找到并撤销。对已自动接管的条目不允许继续把它编辑成自动定价覆盖；可删除，若以后再次未定价再重新关联。无效目标允许在来源仍自动未定价时重新选择。

上游请求使用 `https://github.com/LaoYueHanNi/model-price-table/issues/new`，新标签页打开，安全处理外链。标题 / 正文可通过 URL 编码预填原始模型名、归一化候选、失败原因（无命中 / 歧义）、候选 modelId、feed 版本，并提示用户补充提供商与官方价格依据；原始名作为纯文本处理。**仅打开草稿，不自动提交 issue。** 不附加 API key、请求正文、会话内容、项目路径或用量明细。已手动关联的详情仍提供该入口，便于向上游补充名称；打开链接不修改定价或关联状态。

### 本地持久化、写接口与目录迁移

新增当前数据目录下的 `pricing-associations.json`；文件与云端 `pricing.ccsa.json` 分离，不复用已废弃的 `pricing.json`，不写入 npm 包或上传上游。拟定磁盘契约如下，`version` 是此文件格式版本，`revision` 是写入修订号，均与插件发布版本和 feed 版本无关：

```json
{
  "version": 1,
  "revision": 1,
  "associations": [
    { "sourceModel": "provider/internal-name", "targetModelId": "glm-5.3-flash" }
  ]
}
```

来源和目标必须是非空字符串，不含换行或控制字符，来源按忽略大小写的完整名称比较键唯一；不允许为同一名称的不同大小写保存两个目标。保存、修改、撤销都使用该比较键，展示保留原始拼写。只允许上面声明的字段，格式版本必须为 `1`，修订号必须为非负安全整数。文件不存在等价于空关联、修订号 0；未知格式、重复来源、非法字段或损坏内容须报告存储错误、保留磁盘内容，不自动覆写为空表。自动识别仍可用，人工关联暂不生效，写入被拒绝直到存储问题解决。磁盘目标不存在不是格式错误，而是需展示的失效关联。

后端提供专用关联读取 / 保存 / 撤销接口，沿用现有本机路由的 same-origin 校验、方法限制和 `no-store`；变更只接受 JSON 请求，不通过 GET 写入。客户端只提交来源、目标、当前关联 `revision` 及目录快照标识，不提交价格或任意文件路径。服务端串行化读改写，在锁内检查修订号、当前目录、feed 目标与自动识别状态；并发冲突或目录已切换返回冲突状态，客户端刷新后让用户重试，不能覆盖另一个页面的修改。成功原子写入、增加修订号并返回真实状态；失败不得发布成功状态。重复保存同一关联或撤销已不存在的关联可按幂等操作处理，但不能绕过修订号校验。

新文件加入 `src/migrate.ts` 的自有文件名单。迁移期间暂停关联写入，并排空在途写队列，复制、切目录与清理结束后恢复；读接口始终绑定当前目录快照。通常目标不存在时原样迁移，重启后恢复全部关联。

关联文件单独采用更严格的迁移冲突保护：复制前预检目标已有的同名关联文件，字节不同时中止此次迁移并提示冲突，保留两边文件；内容相同时可复用，只有确认目标内容完整一致后才清理来源。不能沿用普通文件「目标同名优先、同尺寸即可清理」而丢掉用户关联。未知或损坏的关联文件仍按原始内容保护，不因暂时不可读取而删除。此保护只调整新文件的迁移处理，不顺带改变其他自有文件的冲突语义。

### 统一识别上下文、历史重算与既有决策边界

后端统一模型识别入口，结果至少保留原始名、规范 `modelId`、命中方式（精确 ID / 历史 alias / 归一化 ID 或 alias / 正则 / 手动关联），归一化是否去过前缀、失败原因与歧义候选，以及保存关联的生效 / 失效 / 被接管状态。费用、`canonicalName`、模型筛选、未定价列表、请求序列、会话费用、模型详情和定价总览「已用」标记必须消费相同结果，前端只展示与搜索候选，不再独立推断价格。

`readPricingContext` 或其后继入口一次读取有效 feed 与关联快照，编译正则并按原始名缓存识别结果；每个统计响应内保持同一快照。缓存随 feed 内容、关联修订号和目录变化失效，不能只看 feed `version`，不能把正则可接受的所有字符串预先展开到 flat table。响应提供关联来源与状态，使折叠后仍能按原始名撤销。

识别成功后按目标完整规则重新解析 **每条记录当时的时间和上下文**，再分配 `RateKey`、聚合与计算费用。必须处理冻结历史：给 `rollup` 增加定价上下文指纹（有效 feed 的识别与计价内容、关联内容及识别算法修订），旧缓存缺指纹或指纹不同则从原始 JSONL / 有效记录缓存重新构建派生聚合。单纯的同步时间或展示元信息变化无需重建，但新增 / 修改 / 撤销关联、自动接管、feed 规则变化和升级到新识别算法都不能只给旧 `UNPRICED_KEY` 或旧目标的 `RateKey` 套新单价。重建期间及并发读取也不得以旧缓存回写覆盖新指纹；历史源记录缺失时明确报告无法完整重算，不伪造精确费用。原始名和 token 用量不变，日志不做数据迁移。

与已实施记录的关系：

- [废除手工 pricing.json](../implemented/2026-09-05-abolish-manual-pricing-json.md) 继续有效：价格唯一来源仍是云端表，本地只引用已有 ID；云端没有对应模型时仍无法本地编造单价，必须向上游补价。
- [按模型表按定价别名折叠](../implemented/2026-09-10-bymodel-folds-pricing-aliases.md) 的原始名存储、读路径折叠、筛选覆盖同一规范模型继续有效。本提案**拟部分取代**「alias 先写者赢」「所有定价更新无需重建聚合」及「未定价原始名逐字分行 / 精确筛选」三项约定，分别改为同阶段歧义、带指纹的必要重建、完整名称忽略大小写分组 / 筛选；单纯把名称折叠到规范 ID 仍只发生在读路径。
- [定价表总览](../implemented/2026-09-05-pricing-table-overview.md) 的全量云端模型、一模型一行、搜索与用量筛选解耦继续有效；局部选择器复用数据和搜索能力，不把关联名称塞进 feed 模型列表成为独立价目。
- [模型名本身作为定价入口](../implemented/2026-09-10-bymodel-pricing-name-affordance.md) 的已定价入口继续有效；本提案拟扩展未定价行及关联标记的操作入口。
- [daysOfWeek 与三层计价](../implemented/2026-08-29-daily-slots-days-of-week.md) 的规则选择语义继续有效；此处只增加名称识别和确保旧派生状态重新选择规则，不顺带改变现有上下文 token 计算口径。

第一阶段已在旧别名折叠、daysOfWeek 和会话维度记录中标记部分取代关系，并同步更新用户文档；本整体提案不迁移。后续阶段独立编写实施记录，按 [决策记录规范](../README.md) 标记实际取代的部分并更新仍有效事实，不能把旧决定原地篡改成相反决定。

## Alternatives considered

- **直接 contains / 取第一条命中** —— 当前 `glm-5.3-flash` 与 `glm-5.3-flashx` 已构成实际碰撞，结果还依赖 feed 排列顺序。放弃：子串只能用于人工候选搜索，不能据此自动计费。
- **只在归一化阶段忽略大小写，原始精确和正则仍区分大小写** —— 更接近上游识别规则，但同一名字的大小写变化会改变识别阶段，正则别名可能因此失败。放弃：按用户明确要求三个阶段统一忽略大小写；不同大小写不是不同模型，仍保留完整名称和模型变体要求。
- **严格按上游原名识别，不兼容 provider 前缀** —— 协议实现最直接，但用户要求的前缀兼容问题仍在。放弃：在明确声明的插件兼容层提供去前缀候选，保留其余模型身份与正则契约。
- **把每个 provider/model 组合都补进上游 aliases** —— 历史 aliases 已冻结，新增只能写正则；逐个维护网关前缀仍扩大上游维护面。放弃：常规 provider 命名空间在消费端统一兼容，特殊同价命名向上游补正则。
- **仅自动识别、不做本地映射** —— 更轻，但内部代号与 feed 完全异名时仍无解。放弃：保留可发现、可撤销的原始名人工关联。
- **仅本地映射、不自动去前缀** —— 避免归一化误匹配，但每个常规 provider/model 都需手配。放弃：自动兼容与人工补救并存。
- **手动关联插在归一化 / 正则之前或覆盖已定价模型** —— 可以纠正更广泛的本地判断，但用户难以知道上游识别被何时覆盖，本次需求限定为未定价补救。放弃：先走完整自动链，再应用原始名的显式关联；自动命中有误时修上游或使用已有的自维护 feed 配置。
- **恢复完整本地 pricing.json 私有价目覆盖** —— 能本机即刻补价，却重演双来源、整模型覆盖丢失时间 / 档位 / 峰谷规则的问题。放弃：沿用已实施的废除决定，仅保存名称引用。
- **只让用户去定价总览找目标，或手写映射文件** —— 少做一个交互，但关联来源不在眼前、跳转多、保存与撤销不可发现。放弃：在未定价处局部搜索，并提供包含停用 / 失效条目的关联管理。
- **沿用旧 rollup，只替换费率和规范名** —— 更新更快，但旧未定价身份或其他模型的规则身份无法还原目标当时应使用的档位 / 时段。放弃：保留原始事实，指纹变化后重新解析历史记录并生成派生聚合。

## Acceptance criteria

实施时至少满足以下可观察结果；测试使用固定的小型 feed，不依赖公网最新价格或真实当前时间。

| 场景 | 应有结果 |
| --- | --- |
| 名称既是 B 的 modelId，又是 A 的历史 alias / 正则 | 精确 ID 命中 B |
| 精确 alias 命中 A，去前缀候选或正则可命中 B | 原始精确 alias 命中 A |
| `provider/glm-5.3-flash`，feed 有同名短 ID 及 `glm-5.3-flashx` | 去前缀完整命中 flash，绝不命中 flashx |
| `namespace/provider/glm-5.3-flash` | 使用最后一段候选，保留原始名作为记录与关联键 |
| `provider/GLM-5.3`，feed 只有小写 ID、没有对应 alias / 正则 | 去前缀并忽略大小写命中 `glm-5.3` |
| `GLM-5.3`，feed 只有小写 ID | 第一阶段完整名称命中，规范 ID 保留 feed 拼写 |
| feed 同时有 `Foo` 与 `foo` 两行 modelId | 视为重复 ID，校验失败，不作为两个大小写不同的模型计价 |
| 同一模型声明 `Foo` 与 `foo` 历史 aliases | 忽略大小写后是同一名字，命中同一模型一次 |
| 不同模型声明忽略大小写后相同的 alias | 属于跨模型别名冲突，报歧义，不能靠大小写选价 |
| 归一化可命中 A 的 modelId 和 B 的 alias | 归一化 ID 子阶段优先命中 A |
| 原始正则命中 A，而归一化命中 B | 按阶段顺序命中 B |
| 精确均失败，合法正则唯一匹配原始名或去前缀候选 | 使用该模型完整价格规则 |
| 正则多条匹配同一模型 | 唯一模型命中，不报歧义 |
| 同一 alias 跨模型，或两个正则候选命中不同模型 | 未定价并报歧义，不依赖数组顺序，可人工指定 |
| `fast` / `flashx` / `mini` / 不同版本 / 尾部换行 | 未被普通模型宽泛正则错误捕获 |
| 精确与归一化无法命中、仅有大小写不一致的正则别名 | 使用 `i` 标志完整匹配，正确识别同一模型 |
| 大小写变化后的正则输入带 `fast` / `flashx` / `mini` 等不同变体 | `i` 不移除模型身份，普通模型正则仍须拒绝不同变体 |
| 同一未定价完整名称只在大小写上不同 | 分为同一未定价行，关联和筛选覆盖全部大小写变体，原始记录不改写 |
| 保存的目标 ID 在 feed 中仅调整大小写 | 仍关联到同一模型，返回 feed 当前拼写，不报目标失效 |
| 前导、尾随或连续 `/`，或未知名称 | 不产生错误归一化候选；无合法原名命中则未定价 |
| 旧 feed 无 aliasPatterns；真实四项零单价模型 | 历史精确匹配可用；零单价仍显示已定价 |
| 非法正则或字段、重复 modelId | 新同步失败且保留旧镜像；无有效镜像时明确不可用 |

此外须覆盖：

- 局部搜索不改变用量筛选，不访问公网，可搜索未使用的模型；子串搜索仅列候选，保存前须选择唯一目标。无结果、加载失败、取消、写入失败、键盘和层叠弹窗均有明确结果，中英文文案齐全。
- 保存关联后费用、未定价警告、模型详情、筛选、总览已用标记与会话视图一致；折叠行混有自动与人工来源仍能逐项查看和撤销，无双重计数。所有保存条目可在无相关日期用量时管理。
- 关联仅作用于该完整名称及其大小写变体，不影响其他 provider 或无前缀名称；同一名称不能因大小写不同保存两个目标，任一大小写提交撤销都删除同一关联。重启后保持；删除目标、切换 feed、自动接管同目标 / 不同目标、自动识别再次失败均按生命周期显示和计费。撤销后自动结果优先或恢复未定价，不残留缓存关联。
- 关联目标包含历史 timeRules、contextTiers、工作日 dailySlots 的测试，覆盖冻结日期曾未定价、改关联到另一模型、撤销与升级旧 rollup；历史重算正确、token / 请求数不变，缓存不沿用旧 RateKey。
- 文件校验、未知格式、重复来源、并发 revision 冲突、旧目录表单提交、写入与迁移互斥、无冲突迁移、目标同名不同内容的拒绝与源文件保护均有测试。既有其他文件迁移规则不受影响。
- issue 入口打开上游新建草稿，原始名与原因正确编码，特殊字符不能注入页面或链接，不自动提交，也不附加敏感会话 / 项目数据。
- 本次文档修订通过 `node docs/decisions/check.mjs`；实际实施提交另需对应定价、统计、路由、存储 / 迁移及客户端测试和项目要求的检查，并完成上述旧决策的部分取代标记与用户文档更新。

## Risks

- **前缀兼容不证明提供商实际同价**：不同网关可能用相同短名销售不同价格。此层只选上游模型价目作为估算，不能据此声称是网关账单；原始名与命中方式必须可查看。已自动命中的模型不提供人工覆盖，本次主动放弃这类改价需求，修正走上游或自维护 feed。
- **大小写策略与上游不同**：插件按用户约定不以大小写区分模型，所有识别阶段和关联来源统一忽略大小写；上游正则数据格式不变，由消费端固定使用 `i`。同一模型的别名大小写变体去重，重复 modelId 或跨模型别名 / 正则冲突按数据错误或歧义处理，不把大小写当作另一种价格依据。
- **归一化优先于原名正则**：特殊 provider 名称若应指向另一个价目，须以原名的精确 ID / 历史 alias 命中，或调整上游数据；不能期待后置正则覆盖归一化结果。协议升级时要重审这一插件扩展。
- **人工选择错误与 feed 漂移**：用户可能把不同模型关联到一起；展示目标完整规则、历史影响与持续关联标记，支持撤销。自动接管与目标失效显式提示，避免本地选择被静默隐藏。
- **正则执行和协议演进成本**：逐名称扫描正则增加读路径成本，加载时编译、限制为上游有界语法并按快照缓存；未来上游引入新语法须显式升级消费端，不能无校验放行。
- **历史重算成本与源记录完整性**：定价上下文变化会触发冻结聚合重建，首次刷新可能变慢；复用有效原始记录缓存，之后复用带指纹聚合。源日志缺失时无法恢复原始时间 / 上下文，不使用旧聚合伪造完整重算。
- **新增本机写状态与迁移冲突**：关联存储带来并发、异常与迁移负担；原子写、修订号、目录快照和冲突拒绝优先保证用户关联不丢失。此文件不是价格来源，遗留 pricing.json 仍被忽略且不主动删除。
